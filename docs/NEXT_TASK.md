# 次の実装タスク

この文書には、Codexへ渡す依頼文を何度も読み返さずに済むよう、現在実装する一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-4C：基本アイテムスロット

## 目的

室内 `starter_house_interior` と庭 `starter_garden` に、少数の固定アイテムスロットを用意する。

ユーザーは既存アイテムを一件ずつスロットへ割り当て、登録済み背景へ合わせて相対座標を調整し、保存できる。

通常のマップでは、割り当て済みアイテムを既存のローカルSVGアイコンと名前で表示する。個別画像がないアイテムでも空白にならず、外部通信や画像Blobの読込みなしで成立させる。

このMilestoneは、固定された六つの表示スロットだけを扱う。自由な家具配置、スロット追加、アイテムの使用や所持数は扱わない。

## 固定スロット

各マップに三つ、合計六つの固定スロットを持つ。

### 室内

- `interior_slot_1`：初期位置 `{ x: 0.18, y: 0.30 }`
- `interior_slot_2`：初期位置 `{ x: 0.50, y: 0.56 }`
- `interior_slot_3`：初期位置 `{ x: 0.82, y: 0.30 }`

### 庭

- `garden_slot_1`：初期位置 `{ x: 0.20, y: 0.58 }`
- `garden_slot_2`：初期位置 `{ x: 0.50, y: 0.70 }`
- `garden_slot_3`：初期位置 `{ x: 0.80, y: 0.58 }`

正確な定数名とファイル分割は既存構造へ合わせてよい。スロットID、個数、初期順序、初期座標の意味は変更しない。

## このMilestoneで変えないもの

- マップID、マップ種別、地点ID、地点名、地点タイプを変更しない
- 地点配置、出入口接続、代理位置、庭の家の外観位置を変更しない
- マップ内経路、最短経路、移動速度、論理現在地を変更しない
- キャラクターピンの接地点、表示倍率、画像内表示位置を変更しない
- アイテム本体の `itemId`、名前、カテゴリ、説明、タグ、source、画像参照を配置操作で変更しない
- アイテムを所持品から取り除かない
- アイテムの個数、消費、取得、使用、劣化、所有者を追加しない
- スロットを追加、削除、複製、改名しない
- アイテムを地点、人物、出入口、イベントへ結び付けない
- マップ上の個別画像表示、画像倍率、接地点、切抜き設定を追加しない
- `mapDisplayMode` の編集UIを追加せず、このMilestoneのマップ表示は既存アイコンへ固定する
- 画像Blobを加工またはマップ表示のために読込まない
- 新しいマップの作成、複製、削除を追加しない
- IndexedDBバージョンを8へ上げない
- 新しいストア、外部依存、外部通信、APIを追加しない

新しいカスタムマップ作成はMilestone 8B-4Dへ分ける。人物ピンの直接タッチ調整と地点間の中継点動線は、`docs/ROADMAP.md` の将来候補のままとし、このMilestoneへ混ぜない。

## 1. 安定データ

既存 `mapVisuals` ストアと `MapVisualState` または同等のマップ別安定データへ、後方互換な固定スロット状態を追加する。

少なくとも次の意味を持つ構造とする。

```ts
type RelativePoint = {
  x: number;
  y: number;
};

type MapItemSlot = {
  position: RelativePoint;
  itemId: string | null;
};

type MapItemSlotLayout = Record<string, MapItemSlot>;
```

正確な型名は既存構造へ合わせてよい。

意味：

- レコードのキーは固定slotId
- `position` は3:4マップ枠内の相対座標
- `itemId` は既存アイテム一件への安定参照
- `null` は空きスロット

保存規則：

- 室内レコードは室内三スロットだけを持つ
- 庭レコードは庭三スロットだけを持つ
- 保存対象は固定slotIdだけとし、不明slotIdは無視する
- CSS文字列、ピクセル値、DOM座標、Object URL、画像Blobを保存しない
- 編集中の一時ドラフト、選択マップ、選択スロット、フォーカス状態を安定データへ含めない
- 配置は表示上の参照であり、アイテム本体を複製または移動済み状態へ変更しない

## 2. スロットとアイテム参照の検証

六つの固定スロットを、次の安定順序で検証する。

1. `interior_slot_1`
2. `interior_slot_2`
3. `interior_slot_3`
4. `garden_slot_1`
5. `garden_slot_2`
6. `garden_slot_3`

復旧規則：

- 固定スロットが欠けている場合、そのスロットだけを初期位置、`itemId: null` で補う
- 不明slotIdは無視する
- `itemId` が文字列でない、空、制御文字を含む、または現在のアイテム一覧に存在しない場合、そのスロットだけ空にする
- 同じitemIdが複数スロットに保存されている場合、安定順序で最初の一件だけを維持し、後続を空にする
- 一スロットの破損で他スロット、アイテム本体、背景、地点、人物、イベントを捨てない
- 既存DB7レコードにスロット状態がなければ、六つすべてを初期位置、空き状態で補う

純粋関数として少なくとも次を分離する。

- 一マップの固定スロット初期状態を生成する
- 保存値から一スロットずつ位置とitemIdを復元する
- 室内と庭を合わせて重複itemIdを解消する
- 固定スロットと現在のアイテム一覧から、有効なマップ表示を解決する

## 3. 座標の検証と正規化

保存値は0から1の有限数とする。

- 左端0、右端1
- 上端0、下端1
- 基本刻み0.01
- 永続化前に小数第2位相当へ正規化してよい
- `NaN`、`Infinity`、文字列、範囲外を受理しない
- `x`、`y`の片方だけ不正な場合、その成分だけ該当スロットの初期値へ戻す

44px以上のマップ表示を枠内に保つため、編集UIから保存できる中心座標は原則0.05から0.95とする。

スロット位置は地点座標、出入口、代理位置、人物現在地から独立した表示座標とする。

## 4. 一つのアイテムは一枠まで

同じitemIdを同時に複数スロットへ割り当てない。

編集UIで、すでに別スロットへ割り当てられているアイテムを選んだ場合：

- 現在選択中のスロットへitemIdを割り当てる
- 以前のスロットは同じドラフト内で空にする
- 永続状態と通常マップは、保存するまで変更しない
- どのスロットから移動したかを短いメッセージで示す

アイテムは所持品一覧に残る。これは所有権や個数の移動ではなく、マップ表示位置の変更である。

## 5. 設定画面

既存「設定」画面のマップ設定付近へ、`アイテムを配置` または同等の編集操作を一つ追加する。

室内と庭の割当は重複排除を共有するため、一つの編集フローで六スロットを扱い、一回の保存で確定する。

### 5.1 編集開始

編集開始時は、現在の有効な室内・庭スロット状態を一時ドラフトへコピーする。

- 編集開始だけでは永続状態、通常マップ、アイテム本体を変更しない
- 背景画像、地点配置、出入口・代理表示の編集中、保存中、削除確認中は開始しない
- アイテムスロット編集中は背景変更、地点配置、出入口編集を同時に開始しない
- 自律行動などの無関係なStore更新でドラフト、選択マップ、選択スロット、フォーカスを失わない

### 5.2 プレビュー

iPhone縦画面では、室内と庭の3:4プレビューを切替ボタン、タブ、または縦積みで確認できるようにする。横並びを必須にしない。

各プレビューへ次を表示する。

- 現在の背景画像または仮背景
- 保存済み地点配置の読み取り専用マーカー
- 三つのスロット
- 割当済みスロットのアイコンとアイテム名
- 空きスロットを識別できる編集用表示
- 選択中スロットを色だけに依存しない表示

プレビュー上のスロットをタップして選択できるようにしてよい。プレビュー操作で通常マップの移動、イベント、アイテム詳細を開かない。

### 5.3 操作

少なくとも次を提供する。

- 室内と庭の編集対象を切り替える操作
- 三つのスロットから一件を選ぶ操作
- 現在の割当アイテム名または「何も置かない」の表示
- `何も置かない` と既存アイテム一覧を含む選択入力
- 選択中スロットの横位置と縦位置のrange入力
- 現在値の百分率表示
- `このスロットを空にする`
- `このスロットの位置を初期値へ戻す`
- `全スロットの位置を初期配置へ戻す`
- `すべてのアイテムを外す`
- `この配置を保存`
- `キャンセル`

アイテム選択肢には、少なくともアイテム名とカテゴリ名を表示する。

選択入力の順序は、既存アイテム一覧と同じ安定した順序を使う。同名アイテムがあってもitemIdで区別する。

ドラッグ操作は追加してよいが、ドラッグだけを必須にしない。

一つの位置または割当を変えても、他スロットの位置を上書きしない。

### 5.4 保存とキャンセル

- 保存前は編集プレビューだけを更新する
- 保存成功後だけStoreの安定状態と通常マップへ反映する
- 保存失敗時は以前の六スロットを維持し、ドラフトを残す
- キャンセル時は保存済み設定へ戻る
- 初期位置、空き状態への操作もドラフトだけを更新し、保存操作で確定する
- 保存中は二重操作を無効化する
- 成功、移動、解除、失敗を `aria-live` で通知する

## 6. 永続化

IndexedDBバージョン7と既存 `mapVisuals` ストアを維持する。

一つのアイテムを一枠までに保つため、室内と庭の二レコードを一つの `readwrite` transactionで保存する。

- 新しいストアを追加しない
- 二つの `backgroundAssetId` を維持する
- 二つの `locationLayout` を維持する
- 二つの `gatewayVisual` または同等の出入口設定を維持する
- 既存の更新時刻方針へ合わせて両レコードを更新する
- transaction成功後だけ二レコードをメモリ状態へ反映する
- transaction失敗時は両方の旧レコードを維持する
- 通常の全体保存、起動時復元、Safariの履歴復元で設定を失わない
- 一時ドラフトを通常のSaveSnapshotまたは安定レコードへ含めない

RepositoryまたはSaveCoordinatorに、室内と庭のスロット状態をまとめて保存する専用処理を追加してよい。片方ずつ公開する保存処理は、この編集フローから使用しない。

全体リセットでは、六スロットを初期位置、空き状態へ戻す。背景、地点、出入口、人物画像、人物ピン設定、アイテム本体、アイテム画像に関する既存リセット仕様を維持する。

## 7. 通常マップ表示

通常マップでは、有効なitemIdを持つスロットだけを表示する。空きスロットは表示しない。

表示規則：

- 既存 `ItemIcon` または同等のローカルSVGアイコンを使う
- アイテムの `visual.iconKey` を安全なレジストリ経由で解決する
- 未知のiconKeyは既存の `category` フォールバックへ戻す
- アイコンとアイテム名を併記する
- 個別画像、カテゴリ共通画像、Object URLをマップ表示のために読込まない
- `mapDisplayMode` は変更せず、このMilestoneではアイコン表示とする
- 一つのマップにつき最大三件だけを表示する

レイヤー順は、少なくとも次の意味を維持する。

1. 背景
2. 庭の家の外観
3. 配置アイテム
4. 地点ボタン
5. 地点イベント
6. 人物ピン
7. 代理表示

地点、イベント、人物、代理表示の既存操作を優先し、アイテムが重なっても重要操作を奪わないz-indexとする。

配置アイテムは44px以上のボタンとし、次を満たす。

- 視覚上もアイテム名を確認できる
- `aria-label` にアイテム名と「詳細を見る」ことを含める
- タップすると既存のアイテム詳細画面を開く
- タップで人物現在地、マップ、アイテム割当を変更しない
- 画像なしでも同じ操作ができる

## 8. アイテム一覧と詳細

既存のアイテム一覧、登録、詳細、個別画像追加・変更・削除を維持する。

このMilestoneでは、アイテム詳細に配置場所の編集UIを追加しない。配置は設定画面の一つの編集フローから行う。

配置アイテムを通常マップから開いた時は、既存の選択itemIdとアイテム詳細表示を使用する。新しい詳細画面やダイアログを複製しない。

## 9. 自律行動、イベント、移動との分離

アイテムスロットは表示設定であり、次へ影響させない。

- 主人公とパートナーの経路探索
- 自律行動候補と重み
- `inspect_item` の対象選択
- 地点イベントの発生と判定
- 出入口、代理表示、家の外観
- パートナーチャットへ送る相談プロンプト

アイテム配置を保存しても人物を移動させず、イベントを発生させない。

## 10. アクセシビリティとモバイル

- iPhone Safariの縦画面を最優先する
- 320px幅で横スクロールを発生させない
- 主要操作、マップ切替、スロット選択、配置アイテムは44px以上
- range、selectと入力周辺の文字は16px以上
- 選択マップ、選択スロット、空き、割当済みを色だけで示さない
- アイコンだけに意味を依存せず、アイテム名を表示、読み上げする
- キーボードとタッチの両方で操作できる
- フォーカス表示を消さない
- プレビュー更新で不要なフォーカス移動を起こさない
- `prefers-reduced-motion` を維持する

## 11. セキュリティとプライバシー

- 外部通信を追加しない
- アイテム配置、背景、現在地を相談プロンプトへ追加しない
- 動的なアイテム名、カテゴリ名、数値は `textContent` または安全なDOM APIで描画する
- 保存値を検証せずCSSへ渡さない
- `innerHTML`、`eval`、`Function`、動的importを使用しない

## 12. このMilestoneで扱わないもの

- スロットの追加、削除、複製、改名、種類変更
- 自由ドラッグだけに依存する家具配置
- アイテムの回転、表示倍率、接地点、重なり順の個別編集
- マップ上の個別画像、カテゴリ共通画像、サムネイル生成
- アイテムの所持数、消費、取得、使用、贈与、装備
- アイテムを人物、地点、行動、イベントへ結び付ける処理
- `inspect_item` 自律行動の変更
- 新しいカスタムマップの作成、複製、削除
- 人物ピン画像のドラッグ、ピンチ調整
- 地点間の中継点、折れ線動線、自由歩行
- 思い出、バックアップ、PWA
- 本番素材制作

## 手動確認

1. 既存セーブで起動し、背景、地点配置、出入口、代理位置、人物画像、アイテム画像が残っていることを確認する。
2. 「設定」から「アイテムを配置」を開く。
3. 室内の三スロットと庭の三スロットを切り替えて確認する。
4. 室内の一枠へ「マグカップ」、別枠へ「本」を割り当て、位置を変更する。
5. 庭の一枠へ「ジョウロ」を割り当て、位置を変更する。
6. 編集中はプレビューだけが変わり、通常マップへまだ表示されないことを確認する。
7. 「マグカップ」を庭の別枠へ選び、室内の元枠がドラフト上で空になることを確認する。
8. 保存し、室内と庭の割当済みアイテムがアイコンと名前で表示されることを確認する。
9. 空きスロットが通常マップへ表示されないことを確認する。
10. 配置アイテムをタップし、既存のアイテム詳細が開くことを確認する。
11. 個別画像のあるアイテムを配置しても、マップではローカルSVGアイコンで表示されることを確認する。
12. 一枠を空にして保存し、アイテム本体が一覧と詳細へ残ることを確認する。
13. ページを再読込し、六スロットの位置と割当が残ることを確認する。
14. 全位置を初期配置へ戻し、すべてのアイテムを外して保存できることを確認する。
15. 主人公とパートナーを室内と庭へ移動し、経路、出入口、代理表示、家の外観が従来どおり動くことを確認する。
16. 「知らない芽」、自律行動、相談、アイテム登録と画像変更が従来どおり動くことを確認する。
17. 320px幅とiPhone縦画面で横スクロールせず操作できることを確認する。
