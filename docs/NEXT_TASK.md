# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-1：アイテム一件の個別画像

## 目的

Milestone 8Aで作成したアイテム詳細から、端末内のPNG、JPEG、WebP画像を一枚だけ任意登録できるようにする。

ユーザーは次を行える。

- 画像のないアイテムへ画像を追加する
- 登録済み画像を別画像へ変更する
- 登録済み画像だけを削除する
- ページ再読込後も画像を確認する

画像は任意である。画像がない、削除した、壊れている、読込に失敗した場合も、アイテム本体を残し、既存の汎用SVGアイコンで一覧と詳細を成立させる。

ゲームから外部サービスへ画像を送信しない。外部画像URLを保存しない。画像生成APIへ接続しない。

## このMilestoneで変えないもの

- アイテム一覧は引き続き汎用SVGアイコンを使用する
- `mapDisplayMode` は引き続き `"icon"` とする
- マップ上へ個別画像を表示しない
- アイテムの名前、カテゴリ、説明、sourceは画像操作で変更しない
- 画像を削除してもアイテム本体は削除しない
- 既存のマップ、イベント、パートナー設定、自律生活を止めない
- 登録フォームの一時ドラフト保持を維持する

## 扱う画像

受け付ける形式は次だけとする。

- `image/png`
- `image/jpeg`
- `image/webp`

次は拒否する。

- SVG
- GIF
- HEIC、HEIFを含む未対応形式
- MIME typeが空または不明なファイル
- 拡張子だけが画像で内容が対応形式ではないファイル
- 10 MiBを超えるファイル
- 0 byteのファイル

ファイル入力は次を使用する。

```html
<input type="file" accept="image/png,image/jpeg,image/webp">
```

`accept` だけを信頼せず、少なくともMIME type、byte size、先頭バイトの形式を検証する純粋関数またはテスト可能な関数を用意する。

対応する代表的なシグネチャ：

- PNG：`89 50 4E 47 0D 0A 1A 0A`
- JPEG：`FF D8 FF`
- WebP：先頭が `RIFF`、8 byte目から `WEBP`

画像の切抜き、圧縮、回転、色補正、サムネイル生成は行わない。ブラウザが表示する向きに従う。

## 1. アセットデータ

### 1.1 安定ID

アセットにはゲーム側が発行する `assetId` を持たせる。

- `crypto.randomUUID()` を優先する
- 未対応時は `crypto.getRandomValues()` を使う
- `Math.random()` 単独にしない
- ファイル名をIDやIndexedDBキーにしない
- Object URLやData URLをIDとして保存しない

### 1.2 メタデータ

少なくとも次の意味を持つ型を用意する。

```ts
type AssetMetadata = {
  assetId: string;
  kind: "item_image";
  ownerId: string;
  mimeType: "image/png" | "image/jpeg" | "image/webp";
  byteSize: number;
  originalName: string;
  createdAt: string;
  updatedAt: string;
};
```

- `ownerId` は対象アイテムの `itemId`
- `originalName` は表示用情報であり、パスやキーへ使用しない
- 動的なファイル名を `innerHTML` へ渡さない
- `originalName` は制御文字を拒否し、表示用に安全な上限を設ける
- メタデータとBlobを分けて保存する

### 1.3 Blob

BlobはJSON化、Base64化してメインセーブへ入れない。

永続化層では少なくとも次を関連付けて保存する。

```ts
type AssetBlobRecord = {
  assetId: string;
  blob: Blob;
};
```

保存レコードへ既存方式どおり `saveSlotId: "main"` を付与してよい。

### 1.4 アイテム参照

既存の `ItemVisual.imageAssetId` を使用する。

- 画像なしは `null`
- 画像ありは有効な `assetId`
- 空文字、制御文字、過度に長い値を受け入れない
- 起動時のアイテム部分復旧で、`imageAssetId` が不正でもアイテム本体まで捨てない
- 不正な参照は `null` 相当として表示上フォールバックしてよい

## 2. IndexedDB

データベースバージョンを5から6へ上げる。

既存ストアを変更、削除しない。

次を追加する。

- `assets`
- `assetBlobs`

推奨キー：

```ts
assets: [saveSlotId, assetId]
assetBlobs: [saveSlotId, assetId]
```

バージョン5の既存セーブを壊さずに6へ移行する。

- 既存itemsを維持する
- マップ、人物、イベント、相談、パートナー設定、台詞、履歴を維持する
- 既存アイテムの `imageAssetId: null` をそのまま扱う
- アセットが一件もなくても正常起動する

## 3. Repositoryと原子的保存

画像操作専用のRepository APIを用意する。正確な関数名は既存構造へ合わせてよいが、次の意味を分ける。

- 一つのアセットメタデータとBlobを取得する
- 新しい画像をアイテムへ関連付ける
- 既存画像を新しい画像へ置換する
- 画像だけをアイテムから削除する

一覧起動時に全Blobを読み込まない。アイテム詳細を開いた時だけ、そのアイテムの `imageAssetId` に対応するメタデータとBlobを取得する。

### 3.1 追加

一つのIndexedDB transaction内で次を完了する。

1. 対象アイテムが存在することを確認
2. `assets` へメタデータを保存
3. `assetBlobs` へBlobを保存
4. 対象アイテムの `visual.imageAssetId` を新しい `assetId` へ更新

全処理成功後だけStoreへ反映する。

### 3.2 変更

既存画像がある場合は、新しい `assetId` を発行する。

一つのtransaction内で次を完了する。

1. 新しいメタデータを保存
2. 新しいBlobを保存
3. アイテム参照を新しい `assetId` へ更新
4. 以前のメタデータとBlobを削除

途中失敗時は以前の画像とアイテム参照を維持する。

### 3.3 削除

確認後、一つのtransaction内で次を完了する。

1. アイテムの `visual.imageAssetId` を `null` へ更新
2. 対応するメタデータを削除
3. 対応するBlobを削除

画像が既に欠損していても、アイテム参照を安全に `null` へ戻せるようにする。

### 3.4 保存失敗

保存失敗時は次を守る。

- Storeのアイテムを変更しない
- 以前の画像を消さない
- 選択中の新画像とプレビューを残し、再試行またはキャンセルできる
- 読み上げ可能な日本語エラーを表示する
- ゲーム本体と自律生活を続行する

通常の自動保存へBlobを混ぜない。SaveCoordinatorの直列化または同等の排他制御へ、画像操作専用処理を接続する。

## 4. アイテム詳細UI

### 4.1 画像なし

詳細の拡大アイコンと一緒に次を表示する。

- `画像を追加`

押すと画像選択UIを開く。

### 4.2 画像あり

個別画像を詳細の主ビジュアルとして表示し、次を表示する。

- `画像を変更`
- `画像を削除`

一覧は個別画像を読み込まず、従来どおりアイコンを表示する。

### 4.3 選択と確認

画像選択直後には保存しない。

保存前に次を表示する。

- 選択画像のプレビュー
- ファイル名
- 形式
- 容量
- `この画像を保存`
- `選び直す`
- `キャンセル`

`この画像を保存` の明示操作後だけ永続化する。

同じファイルを再選択できるよう、必要に応じてfile inputの値を安全に初期化する。

### 4.4 削除確認

`画像を削除` を押しただけでは削除しない。

確認画面または確認ダイアログで次を明記する。

- 画像だけを削除する
- アイテム本体、名前、カテゴリ、説明は残る

明示的な `画像だけを削除する` 操作後に実行する。

### 4.5 状態表示

少なくとも次の状態を区別する。

- アイコン表示
- 画像読込中
- 個別画像表示
- 新画像の確認中
- 保存中
- 削除確認中
- エラー

画像読込中や失敗時も、空白の大枠を出さずアイコンを表示する。

## 5. 画像表示とObject URL

Object URLは画面表示専用とし、保存しない。

- 同じ `assetId` のObject URLをStoreの無関係な更新ごとに作り直さない
- パートナーの移動や行動による再描画でBlobを再読込し続けない
- 選択プレビューを変更、キャンセルした時は古いURLをrevokeする
- 詳細から離れた時、対象assetが変わった時、画像削除時は不要なURLをrevokeする
- revoke済みURLを再利用しない

App配下の小さなcontrollerまたはcache等、ライフサイクルを明示できる構造を使用する。Object URLを安定データやSaveSnapshotへ入れない。

Blob取得中に別アイテムへ移動した場合、古い非同期結果を現在画面へ誤表示しない。assetIdまたは要求世代を照合する。

## 6. フォールバック

個別画像を表示するには次が一致している必要がある。

- アイテムの `imageAssetId`
- メタデータの `assetId`
- メタデータの `ownerId` とアイテムの `itemId`
- 許可されたMIME type
- 対応するBlob

一つでも欠ける、壊れる、読込に失敗する場合は、詳細で既存の拡大SVGアイコンへ戻る。

- アイテム本体を削除しない
- アプリ起動を失敗させない
- 一覧を壊さない
- 自動で別アイテムの画像を流用しない
- 破損データを `innerHTML` へ渡さない

カテゴリ共通画像の実画像はこのMilestoneではまだ扱わない。したがって、この段階の詳細表示順は次とする。

1. 読込に成功した個別画像
2. 拡大した汎用SVGアイコン

将来、二つの間へカテゴリ共通画像を追加できる構造にする。

## 7. アクセシビリティとモバイル

- 最小幅320pxで横スクロールを発生させない
- 操作領域を44px以上にする
- file inputを含む入力文字を16px以上にする
- ホバー必須にしない
- 画像にはアイテム名を使った代替テキストを付ける
- 装飾SVGは `aria-hidden="true"`
- ファイル名、形式、容量をテキストでも示す
- 保存、削除、エラー結果を `role="status"` または適切な `aria-live` で通知する
- ダイアログを使う場合は閉じた後に起点へフォーカスを戻す
- 色だけで状態を区別しない

## 8. セキュリティとプライバシー

- 外部通信を追加しない
- 外部URLを生成、保存、読込しない
- 画像内容をパートナーチャットへ含めない
- ファイルの絶対パスを取得、表示、保存しない
- ファイル名をHTMLとして解釈しない
- SVGを画像ファイルとして受け付けない
- `eval`、`Function`、動的importを使用しない
- Blob URLはUI表示以外へ使用しない

## 9. このMilestoneで扱わないもの

- カテゴリ共通画像の実画像
- サムネイル生成
- 画像の切抜き、圧縮、回転、編集
- 複数画像の登録
- 画像の並べ替え
- アイテム一覧へのサムネイル表示
- マップ上の個別画像表示
- `mapDisplayMode` の編集UI
- アイテムのマップ配置
- アイテム本体の削除
- キャラクターピン
- 代理アイコン画像
- 室内、庭背景
- 地点マッピング
- 出入口接続編集
- カスタムマップ
- 思い出CG
- バックアップ書出し、読込
- PWA
- 外部画像URL
- 画像生成API

## 10. テスト

少なくとも次を自動テストする。

### 10.1 検証

- PNG、JPEG、WebPの正しい形式とシグネチャを受理する
- MIME typeと内容が一致しないファイルを拒否する
- SVG、GIF、不明形式、0 byte、10 MiB超を拒否する
- originalNameの制御文字と上限を検証する
- assetIdとimageAssetIdの不正値を拒否または安全にnull扱いする

### 10.2 状態

- ファイル選択だけではアイテムを変更しない
- 保存成功後だけ `imageAssetId` を変更する
- 保存失敗時は以前の `imageAssetId` と画像を維持する
- 変更成功時は古いアセットを削除する
- 削除確認を開いただけでは削除しない
- 削除成功後だけ `imageAssetId` をnullへする
- 画像操作で名前、カテゴリ、説明、sourceを変更しない
- 登録フォームの一時ドラフト保持を壊さない

### 10.3 永続化

- 新規画像のメタデータ、Blob、アイテム参照を同時保存する
- 置換を原子的に行う
- 削除を原子的に行う
- バージョン5から6への移行で既存データを維持する
- BlobをSaveSnapshotへ含めない
- 一覧読込時に全Blobを取得しない
- 詳細を開いた対象のBlobだけを取得する
- 欠損メタデータ、欠損Blob、owner不一致でもアイコンへ戻る

### 10.4 Object URL

- 同じassetIdで不要にURLを作り直さない
- 選び直し、キャンセル、画面離脱、削除で不要URLをrevokeする
- 古い非同期取得結果を別アイテムへ表示しない

既存の移動、イベント、相談、パートナー設定、アイテム登録、保存復元テストを維持する。

- 画像削除後もアイテム本体が残る
- ページ再読込後も画像が表示される
- 欠損、破損画像があっても拡大アイコンへ戻る
- 保存失敗時に以前の画像とアイテム参照を維持する
