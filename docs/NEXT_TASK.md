# 次の実装タスク

この文書には、Codexへ渡す依頼文を何度も読み返さずに済むよう、現在実装する一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-4D-3：出入口・代理位置・基本アイテムスロット

## 目的

Milestone 8B-4D-2で地点を保存できるようになった室内と庭のカスタムマップ下書きへ、次の仕上げ設定を追加する。

- 室内と庭のカスタム地点を一件ずつ選ぶ双方向出入口
- 表示中マップごとの代理アイコン位置
- 庭に表示する家の外観位置
- 室内三枠、庭三枠の基本アイテムスロット

室内と庭の二件を一つの編集ドラフトとして扱い、一回の明示保存で二件の下書きを同じIndexedDB transaction内へ更新する。

このMilestoneではカスタムマップ下書きだけを変更する。通常マップ、主人公とパートナーの現在地、経路、自律行動、イベント、現在の出入口、現在の代理位置、現在のアイテム配置へはまだ反映しない。

## このMilestoneで変えないもの

- runtimeの `MapId` unionを変更しない
- 実行マップは `starter_house_interior` と `starter_garden` の二件を維持する
- 三枚目以降の実行マップを追加しない
- 表示中マップ、主人公とパートナーの `mapId`、`locationId` を変更しない
- 現在の通常マップの地点、出入口、代理位置、庭の家の外観位置を変更しない
- 現在の通常マップの基本アイテムスロットと割当を変更しない
- アイテム本体、所持状態、カテゴリ、個別画像、画像Blobを変更しない
- 自律行動候補、行動重み、固定台詞、イベント、最短経路、移動速度を変更しない
- 現在の背景画像を複製、移動、所有者変更しない
- 新しい画像アップロード、画像形式、画像上限、Object URL生成経路を追加しない
- IndexedDBバージョンを9へ上げない
- 新しいストア、外部依存、外部通信、API接続を追加しない

## 1. 前提となる二件の下書き

対象は既存 `customMapDrafts` ストアの次の二件だけとする。

```ts
type CustomMapTargetId =
  | "starter_house_interior"
  | "starter_garden";
```

編集を開始できる条件：

- 室内と庭の下書きが両方保存済みである
- 両方の下書きに、Milestone 8B-4D-2で保存された有効な `locations` が一件以上ある

片方の下書きがない場合は、先に下書きを作る案内を表示する。

片方または両方の `locations` が空の場合は、先に `地点を編集` を開いて `地点設定を保存` する案内を表示する。このMilestoneの保存操作で地点を暗黙作成または暗黙保存しない。

下書き名、`status: "draft"`、`locations`、`createdAt`を維持し、仕上げ設定の保存時は両方の `updatedAt` を同じ時刻へ更新する。

## 2. 安定データ

既存の `CustomMapDraft` または同等のレコードへ、次の意味を持つ値を後方互換に追加する。

```ts
type RelativePoint = {
  x: number;
  y: number;
};

type CustomGatewayVisual = {
  gatewayLocationId: string;
  proxyPosition: RelativePoint;
  entryAffordancePosition: RelativePoint | null;
};

type CustomMapItemSlot = {
  position: RelativePoint;
  itemId: string | null;
};

type CustomMapItemSlotLayout = Record<string, CustomMapItemSlot>;

type CustomMapDraft = {
  saveSlotId: "main";
  targetMapId: CustomMapTargetId;
  name: string;
  status: "draft";
  locations: CustomMapLocation[];
  gatewayVisual: CustomGatewayVisual;
  itemSlots: CustomMapItemSlotLayout;
  createdAt: string;
  updatedAt: string;
};
```

正確な型名、ファイル名、既存型の再利用、関数分割は既存構造へ合わせてよい。

室内レコード：

- `entryAffordancePosition` は常に `null`

庭レコード：

- `entryAffordancePosition` は家の外観ボタンを表示する相対座標

保存しないもの：

- 編集画面の開閉状態
- 選択中のマップ、スロット
- 入力フォーカス、スクロール位置
- 保存中、エラー、確認等の一時UI状態
- DOM座標、CSS文字列、ピクセル値、Object URL
- 地点間の `connectedLocationIds`
- 通常マップへ反映済みかを示す状態
- アイテム個別画像のURLまたはBlob

## 3. 双方向出入口

室内下書きのカスタム地点一件と、庭下書きのカスタム地点一件を一組として選ぶ。

保存値：

- 各下書きの `gatewayVisual.gatewayLocationId`

有効条件：

- 文字列である
- 対象下書きの有効な `locations` に同じ `locationId` が存在する
- 室内側と庭側が両方とも有効である

片側だけ有効な接続を採用しない。

復旧規則：

1. 保存された室内と庭のIDが両方有効なら、その組を維持する
2. 両方の保存値がない初回編集では、現在の通常マップで選ばれている出入口IDが各下書き地点にも存在する場合、その組を編集用初期値として使う
3. それ以外は、室内下書きと庭下書きの配列先頭地点を一件ずつ安全な初期出入口として使う
4. 一方が欠損、不明、削除済みの場合は、両方の出入口IDを同じ復旧規則で一組として戻す
5. 出入口IDを復旧しても、有効な代理位置、家位置、アイテムスロット、下書き名、地点は維持する

出入口は地点タイプではない。`general`、`cooking`等のどの地点タイプも出入口として選択でき、地点タイプ自体は変更しない。

このMilestoneでは出入口を通常マップの移動グラフへ適用しない。Milestone 8B-4D-4で通常マップへ反映する際に、選ばれた二地点へ双方向gatewayを生成する。

## 4. 代理アイコン位置

各下書きへ一件ずつ `proxyPosition` を持つ。

意味：

- 室内を表示中に庭側の人物を示す代理アイコン位置
- 庭を表示中に室内側の人物を示す代理アイコン位置

検証：

- `x`、`y`は有限数だけを受理する
- 保存値として0から1を受理する
- `x`、`y`の片方だけ不正な場合、その成分だけ安全な初期値へ戻す
- 永続化前に小数第2位相当へ正規化してよい
- UIでは中心位置を原則0.05から0.95に制限する
- UIの基本刻みは0.01

初期値と復旧：

1. 保存済みの有効値があれば維持する
2. 保存値がない初回編集では、現在の通常マップの代理位置が有効なら編集用初期値として使う
3. それ以外は、対象下書きで選ばれた出入口地点の `position` を使う

代理位置を変更しても人物の実際の現在地、出入口地点、地点位置を変更しない。

## 5. 庭の家の外観位置

庭下書きだけに `entryAffordancePosition` を持つ。

検証：

- `x`、`y`は有限数だけを受理する
- 保存値として0から1を受理する
- `x`、`y`の片方だけ不正な場合、その成分だけ安全な初期値へ戻す
- 永続化前に小数第2位相当へ正規化してよい
- UIでは家の外観ボタンを枠内に保つため、原則0.15から0.85に制限する
- UIの基本刻みは0.01

初期値と復旧：

1. 保存済みの有効値があれば維持する
2. 保存値がない初回編集では、現在の通常マップの家の外観位置が有効なら編集用初期値として使う
3. それ以外は `{ x: 0.50, y: 0.18 }` を使う

室内下書きの `entryAffordancePosition` は保存値にかかわらず `null` へ正規化する。

## 6. 基本アイテムスロット

各下書きへ固定三枠を持つ。slotIdは既存のMilestone 8B-4Cと同じ安定IDを使う。

室内：

```text
interior_slot_1
interior_slot_2
interior_slot_3
```

庭：

```text
garden_slot_1
garden_slot_2
garden_slot_3
```

- スロットの追加、削除、改名、並び替えは行わない
- 各スロットは相対 `position` と、任意の `itemId` 一件を持つ
- 空きスロットは `itemId: null`
- itemIdは既存 `items` ストアに存在するアイテムだけを受理する
- 不明、空、型違い、制御文字を含むitemIdは `null` へ戻す
- アイテム本体、説明、カテゴリ、画像、所持状態を変更しない

位置検証：

- `x`、`y`は有限数だけを受理する
- 保存値として0から1を受理する
- 片方だけ不正な場合、その成分だけ安全な初期位置へ戻す
- 永続化前に小数第2位相当へ正規化してよい
- UIでは原則0.05から0.95に制限する
- UIの基本刻みは0.01

初回編集：

- 保存された下書きスロットがない場合、現在の通常マップの同じslotIdの位置と割当を編集用初期値として使う
- 現在値が壊れている場合は既存の `ITEM_SLOT_PRESETS` または同等の固定初期位置へ戻す
- 初期値の生成だけではIndexedDBへ書き込まない
- 明示保存後は下書きの独立データとなり、その後の通常マップ側アイテム配置へ自動追従しない

## 7. アイテム重複規則

同じ `itemId` は、室内と庭を合わせた下書き六枠のうち一枠だけへ割り当てられる。

- 別の枠で同じアイテムを選んだ場合、編集ドラフト上で元の枠を空にして新しい枠へ移す
- 復元時に重複がある場合、`interior_slot_1`、`interior_slot_2`、`interior_slot_3`、`garden_slot_1`、`garden_slot_2`、`garden_slot_3` の順で最初の一件だけを維持し、後続を `null` へ戻す
- 重複解消でアイテム本体を削除しない

この一枠制約はカスタム下書き六枠の中だけに適用する。

同じアイテムが現在の通常マップに配置されていても、下書きへ一件置くことを許可する。下書きは未反映の設計データであり、通常マップの割当を解除しない。

## 8. 地点編集との整合

Milestone 8B-4D-2の地点編集、下書き名編集、今回の仕上げ設定は、互いの安定データを失わない。

- 下書き名の保存で `locations`、`gatewayVisual`、`itemSlots` を維持する
- 地点設定の保存で下書き名、`gatewayVisual`、`itemSlots` を維持する
- 仕上げ設定の保存で下書き名、`locations`、`createdAt` を維持する

仕上げ設定の保存後に、地点編集で選択中の出入口地点を削除することは許可する。

その場合：

- 地点保存時にgatewayを暗黙で別地点へ変更しない
- 次に仕上げ設定を開いた時、両側の出入口IDを安全な組へ復旧してプレビューする
- ユーザーが仕上げ設定を明示保存した時に復旧後の組を永続化する
- Milestone 8B-4D-4の完成検証でも、存在しない出入口地点を不採用にする

## 9. 設定画面

既存の `カスタムマップ下書き` 区画へ、二件をまとめて編集する `出入口とアイテム枠を編集` または同等の操作を追加する。

開始条件を満たさない場合はボタンを無効化するか表示せず、次を短い日本語で案内する。

- 室内と庭の下書きを作る
- 両方で地点設定を保存する

一度に編集できるのはこの仕上げ設定一件だけとする。

背景変更、通常地点配置、通常出入口、通常アイテムスロット、カスタム地点、下書き名等の別エディターと同時編集させない。

## 10. 編集プレビュー

室内と庭を切り替えるタブまたは同等の明確な操作を用意する。

各3:4プレビューに表示する：

- 現在登録されている対象枠の背景画像
- 背景がない、または読込失敗時の既存仮背景
- 保存済みカスタム地点と地点名
- 選択中の出入口地点を色だけに依存しない表示
- 編集中の代理アイコン位置
- 庭だけの家の外観位置
- 三つのアイテムスロット
- 割当済みアイテムのローカルSVGアイコンと名前
- 選択中スロットを色だけに依存しない表示
- 下書き名、室内／庭、通常マップへ未反映であること

プレビューに表示しない：

- 現在通常マップの地点を別レイヤーで重複表示すること
- 主人公とパートナーの人物ピン
- 実際の別マップ人物
- イベント
- 現在通常マップの配置アイテム
- 個別画像Blob、Object URLを必要とするアイテム画像

地点マーカー、代理位置、家位置、アイテム枠は編集プレビューの操作だけに使い、人物移動、イベント開始、アイテム詳細表示、通常設定の変更を起こさない。

## 11. 編集操作

少なくとも次を提供する。

共通：

- 室内／庭のプレビュー切替
- `仕上げ設定を保存`
- `キャンセル`

各マップ：

- 出入口地点のselectまたは同等の一覧操作
- 代理位置の横位置range
- 代理位置の縦位置range
- 横位置、縦位置の百分率表示

庭だけ：

- 家の外観位置の横位置range
- 家の外観位置の縦位置range
- 横位置、縦位置の百分率表示

アイテムスロット：

- 三枠から一枠を選択
- 既存アイテムまたは `置かない` を選択
- `この枠から外す` または同等の操作
- 選択スロットの横位置range
- 選択スロットの縦位置range
- 横位置、縦位置の百分率表示

直接ドラッグ操作は追加してよいが必須にしない。select、地点一覧、スロット選択、range入力を必ず残し、タッチ操作だけを必須にしない。

スロット位置の追加プリセットや高度な家具配置操作は作らない。

## 12. 保存とキャンセル

室内と庭の仕上げ設定を一回の明示保存で確定する。

保存時：

- 両方の下書きと有効な地点を再読込または同等に検証する
- 出入口を二件一組として検証する
- 代理位置、庭の家位置、六スロットの位置を検証する
- itemIdを現在の有効アイテム一覧で検証する
- 六枠の重複itemIdを解消する
- 下書き名、status、locations、createdAtを維持する
- 両方のgatewayVisualとitemSlotsを更新する
- 両方のupdatedAtを同じ現在時刻へ更新する
- `customMapDrafts` の室内と庭の二レコードを一つのreadwrite transactionで更新する
- 保存成功後だけメモリ上の保存済み下書きを更新する

保存失敗時：

- 室内と庭の以前の保存済み下書きを両方維持する
- 片方だけ新しい値へ更新しない
- 編集中の二件分のドラフト、選択中マップ、選択スロットを残す
- 再試行またはキャンセルできる
- 短い自然な日本語で知らせる

キャンセル時：

- 二件分の仕上げ設定ドラフトを破棄する
- 保存済み下書きへ戻す
- IndexedDBへ書き込まない
- 通常マップへ反映しない

## 13. 永続化

IndexedDBバージョン8と既存 `customMapDrafts` ストアを維持する。

- DB9へ上げない
- 新しいストアを追加しない
- 室内と庭の一対象枠一レコードを維持する
- 通常オートセーブで下書きを上書きしない
- 仕上げ設定保存はSaveCoordinatorまたは同等の既存排他基盤を通す
- 二件の更新を一つのIndexedDB transactionに含める
- transaction失敗時は両方を以前の状態へ保つ
- 通常世界オートセーブ、背景保存、下書き名保存、地点保存と競合してもデータを失わない
- 古い非同期結果が新しい編集状態を上書きしない
- `mapVisuals`、`assets`、`assetBlobs`、`items`、`characters`、`events`、相談、履歴を変更しない

Repositoryの更新APIは既存レコード全体を安全に復元してから、`gatewayVisual`、`itemSlots`、`updatedAt`だけを差し替える。

## 14. 無関係な再描画

パートナー自律行動、保存状態、時刻等の無関係なStore更新が発生しても、次を失わない。

- 編集中であること
- 室内と庭の二件分のドラフト
- 選択中マップ
- 選択中スロット
- 出入口選択
- 代理位置、家位置、スロット位置
- itemId割当
- 保存失敗メッセージ

selectまたはrange操作中に画面が閉じたり、スクロール位置が大きく飛んだりしないよう既存の再描画対策を維持する。

## 15. 通常マップとの分離

編集、保存、再読込を行っても、このMilestoneでは次を一切変更しない。

- `AppState.mapVisuals`
- runtimeの `starterMaps`
- 主人公とパートナーの現在地
- 表示中マップ
- 最短経路グラフ
- 自律行動の目的地
- 「知らない芽」の位置と進行
- 現在の出入口と代理表示
- 現在の庭の家の外観位置
- 現在の基本アイテムスロット
- 通常マップに表示中のアイテム

下書きの出入口、代理位置、家位置、アイテム枠は設定画面の編集プレビューだけに描画する。

## 16. 背景、人物画像、アイテム画像との関係

- 下書きは背景Asset IDまたはBlobを複製保存しない
- 現在の対象枠背景をプレビューへ利用する
- 背景変更後は仕上げプレビューも新しい背景へ追従する
- 背景削除後は仮背景へ戻る
- 背景変更で保存済み仕上げ設定を変更しない
- 人物画像をプレビューの代理マーカーへ読み込むことを必須にしない
- アイテムスロットはローカルSVGアイコンと名前で成立させる
- アイテム個別画像Blobを仕上げプレビューのために読まない
- 新しいObject URL管理経路を追加しない

## 17. 全体リセットと下書き削除

既存の全体リセットまたは下書き全体の削除で対象 `customMapDrafts` レコードが消えるため、仕上げ設定専用の別ストアや孤立レコードを作らない。

- 下書き全体を削除すると、そのレコード内のgatewayVisualとitemSlotsも削除される
- 背景、通常マップ、アイテム本体、画像Blobは下書き削除の対象にしない
- 全体リセット後は下書きなしに戻る既存仕様を維持する

## 18. UIとアクセシビリティ

- iPhone Safariの縦画面を優先する
- 最小幅320pxで横スクロールを発生させない
- 主要操作、マップタブ、スロット選択を44px以上にする
- select、range周辺の文字を16px以上にする
- 入力へ明示ラベルを付ける
- 室内／庭、選択中出入口、代理位置、家位置、選択中スロット、空き枠を色だけで区別しない
- 出入口の二地点を文字で確認できるようにする
- 割当アイテム名を文字で読めるようにする
- 保存中、保存成功、保存失敗、開始条件不足、重複アイテム移動を `aria-live` または同等の方法で知らせる
- 保存中は二重保存、対象切替、別エディター開始を防ぐ
- ホバーを必須にしない
- フォーカス表示を消さない
- 3:4プレビューが画面幅を押し広げない

## 19. セキュリティとプライバシー

- 下書き名、地点名、アイテム名を安全なDOM APIで描画する
- 保存値を検証せずselect、CSS座標、item参照へ渡さない
- `innerHTML`、`eval`、`Function`、動的importを使用しない
- 外部通信を追加しない
- 背景、地点、アイテム、下書き内容を外部へ送信しない
- 相談プロンプトへ今回の下書き設定を追加しない

## 20. このMilestoneで扱わないもの

- 下書きの通常マップへの反映、切替、公開状態
- runtimeマップ定義の生成
- 人物現在地の移行
