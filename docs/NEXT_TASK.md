# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-3A：主人公とパートナーのキャラクターピン画像

## 目的

主人公 `user` とパートナー `cody` へ、端末内のPNG、JPEG、WebP画像を一枚ずつ任意登録できるようにする。

登録画像は次へ使用する。

1. 現在表示中のマップにいる人物のキャラクターピン
2. 別マップにいる人物を出入口へ示す代理表示
3. 設定画面のプレビュー

画像は任意である。画像がない、削除した、壊れている、参照が不正、読込に失敗した場合も、既存の文字マーカー `U`、`C` または現在のmarkerを表示し、移動、自律行動、代理表示を継続する。

## このMilestoneで変えないもの

- `CharacterId` は `"user" | "cody"` のままにする
- パートナーの内部IDを表示名に合わせて変更しない
- パートナーゲーム設定、revision、台詞を変更しない
- 人物の現在地、移動経路、速度、代理位置を変更しない
- マップ背景は現在の仮表示を維持する
- 地点座標、出入口、接続グラフを変更しない
- ピンの接地点調整UI、表示倍率UI、自由な切抜きUIを追加しない
- アイテム画像とカテゴリ共通画像の挙動を変更しない
- IndexedDBバージョンは6のままとする
- `assets`、`assetBlobs` ストアを再作成、削除しない
- 外部通信、画像生成API、クラウド保存を追加しない

室内・庭背景、接地点、表示倍率、自由な切抜き、カスタムマップはMilestone 8B-3B以降へ分ける。

## 1. キャラクター参照

既存 `CharacterState` へ、任意の画像参照を追加する。

意味として少なくとも次を持つ。

```ts
type CharacterState = {
  characterId: "user" | "cody";
  name: string;
  marker: string;
  mapId: MapId;
  locationId: string;
  imageAssetId: string | null;
};
```

正確なフィールド分割は既存構造へ合わせてよいが、次を守る。

- 初期値は `null`
- 既存セーブでフィールドがない場合は `null`
- 空文字、制御文字、過度に長い値は `null` 相当として部分復旧する
- 不正な画像参照だけで人物、位置、名前、markerを捨てない
- `imageAssetId` は安定データであり、Object URLやData URLを保存しない
- リセット時は両人物の画像参照を `null` へ戻し、画像アセットも安全に削除する

## 2. アセット種類

既存アセット基盤を一般化し、人物ピン画像を表せるようにする。

少なくとも次の意味を扱う。

```ts
type AssetKind = "item_image" | "character_pin";

type AssetMetadata = {
  assetId: string;
  kind: AssetKind;
  ownerId: string;
  mimeType: "image/png" | "image/jpeg" | "image/webp";
  byteSize: number;
  originalName: string;
  createdAt: string;
  updatedAt: string;
};
```

人物画像では次を固定する。

- `kind` は `"character_pin"`
- `ownerId` は `"user"` または `"cody"`
- 一人物につき現在画像は最大一枚
- 新しい画像へ変更する場合は新しい `assetId` を発行する
- アイテム画像の `kind: "item_image"` と検証、保存、取得を壊さない

既存 `itemImages.ts` の責務を共通画像検証へ分ける、または人物用の薄いラッパーを追加してよい。不要な大規模リネームは行わない。

## 3. 受け付ける画像

対応形式と基本検証はアイテム個別画像と同じとする。

- PNG `image/png`
- JPEG `image/jpeg`
- WebP `image/webp`
- 最大10 MiB
- 0 byte拒否
- MIME typeと先頭バイトの一致を検証
- SVG、GIF、HEIC、HEIF、不明形式を拒否
- originalNameの制御文字と長さを検証

ファイル入力は次を使用する。

```html
<input type="file" accept="image/png,image/jpeg,image/webp">
```

画像の圧縮、回転補正、実Blobの切抜き、サムネイル生成は行わない。

ピンと代理表示ではCSSの固定枠へ `object-fit: cover`、中央寄せを使用し、表示上だけ正方形または円形へ切抜く。元Blobは変更しない。

## 4. 設定画面

既存の下部ナビゲーション `settings` を、今回の範囲だけ実画面にする。

画面名は「設定」または「ふたりの見た目」とし、少なくとも次を表示する。

### 4.1 主人公

- 見出し「主人公」
- 現在の画像またはmarkerフォールバック
- `画像を追加` または `画像を変更`
- 画像がある場合 `画像を削除`

### 4.2 パートナー

- 現在の表示名を見出しまたはラベルへ使用する
- 内部ID `cody` をユーザー向け表示へ露出しない
- 現在の画像またはmarkerフォールバック
- `画像を追加` または `画像を変更`
- 画像がある場合 `画像を削除`

### 4.3 選択後

画像選択だけでは保存しない。

保存前に次を表示する。

- 選択画像のプレビュー
- ファイル名
- 形式
- 容量
- `この画像を保存`
- `選び直す`
- `キャンセル`

画像追加、変更、削除は主人公とパートナーで独立させる。片方の操作中に、もう片方の画像状態を上書きしない。

保存中、削除中は対象人物の二重操作を無効化する。別タブへ移動しても、遅れて完了した処理が現在画面の別人物プレビューへ触れないよう世代照合する。

## 5. 保存と原子性

DBバージョンは6のまま、既存 `assets`、`assetBlobs`、`characters` ストアを使用する。

### 5.1 追加

一つのIndexedDB transactionまたは同等の原子的処理で次を完了する。

1. 対象 `characterId` が `user` または `cody` であることを確認
2. `assets` へ `character_pin` メタデータを保存
3. `assetBlobs` へBlobを保存
4. 対象人物の `imageAssetId` を新しい `assetId` へ更新

全処理成功後だけStoreへ反映する。

### 5.2 変更

一つの処理で次を完了する。

1. 新アセットのメタデータとBlobを保存
2. 人物参照を新 `assetId` へ更新
3. 旧 `character_pin` メタデータとBlobを削除

途中失敗時は旧画像と人物参照を維持する。

### 5.3 削除

確認後、一つの処理で次を完了する。

1. 対象人物の `imageAssetId` を `null` へ更新
2. 対応する `character_pin` メタデータを削除
3. 対応するBlobを削除

画像が既に欠損していても人物参照を `null` へ戻せるようにする。

### 5.4 保存失敗

- Storeの人物参照を変更しない
- 旧画像を消さない
- 選択中の新画像とプレビューを残す
- 再試行またはキャンセルできる
- 読み上げ可能な日本語エラーを表示する
- マップ移動、自律生活、アイテム操作を継続する

通常のSaveSnapshotへBlob、Object URL、プレビュー状態を含めない。

## 6. 画像取得とキャッシュ

人物画像はマップ表示で継続利用するため、無関係な再描画ごとにIndexedDBを読み直したりObject URLを再生成したりしない。

人物ごと、または `assetId` ごとの小さなキャッシュを用意する。

守ること：

- 同じ `assetId` は既存Object URLを再利用する
- パートナーの自律移動、台詞、イベント状態更新だけではBlob取得を再開始しない
- `imageAssetId` が変わった時だけ新しい画像を取得する
- 画像変更、削除、リセット、アプリ破棄時に不要URLをrevokeする
- 古い取得結果を新しい人物画像へ誤表示しない
- ownerId、kind、assetId、Blobの存在を照合する
- 欠損、破損、owner不一致、kind不一致時はmarkerへ戻る
- 読込失敗を無限再試行しない

二人分だけなので、一覧用サムネイルストアは追加しない。

## 7. マップ上の人物ピン

現在の `character-pin` の位置、移動、aria-labelを維持する。

### 7.1 画像あり

検証済み画像を固定枠内へ表示する。

- 画像は装飾扱いで `alt=""` または `aria-hidden="true"`
- 親の `role="img"` と `aria-label="人物名：場所"` を維持する
- `object-fit: cover`
- 中央寄せ
- 画像が枠外へはみ出さない
- 320px幅でもマップを圧迫しない
- 主人公とパートナーを色だけで区別しない。既存の枠、名前、marker等の差を必要に応じて維持する

### 7.2 画像なしまたは失敗

現在の `marker` テキストをそのまま表示する。

人物名、現在地、移動判定は画像状態に依存させない。

## 8. 別マップ代理表示

現在の代理表示ボタン、位置、押下時の居場所ダイアログを維持する。

- 一人だけ別マップにいる場合、その人物の画像を小さな固定枠へ表示する
- 画像がない場合は既存markerを表示する
- 複数人対応の型やDOMを壊さない
- 現在のMVPは二人だけなので、新しい人数制限や複数パートナー機能は追加しない
- 代理画像も同じキャッシュ済みObject URLを再利用する
- CSSによる中央切抜きだけを行う
- 代理表示の説明テキストとaria-labelを維持する

## 9. 部分復旧

起動時に次を独立して扱う。

- 人物レコードが有効で画像参照だけ不正なら、画像参照を `null` にして人物を復元
- メタデータがない、Blobがない、kind不一致、owner不一致ならmarker表示
- 一人の画像が壊れても、もう一人の画像、人物位置、ゲーム本体を復元
- 壊れた人物画像を理由にアイテム画像を削除しない
- 孤児アセットの一括掃除は今回必須にしない

## 10. セキュリティとプライバシー

- 外部通信しない
- 画像をパートナーチャットや相談プロンプトへ含めない
- 外部URLを保存、読込しない
- ファイルの絶対パスを取得、表示、保存しない
- ファイル名を `innerHTML` へ渡さない
- ユーザー画像をSVGやHTMLとして解釈しない
- `eval`、`Function`、動的importを使用しない
- Object URLは表示専用で、安定データへ保存しない

## 12. テスト

少なくとも次を自動テストする。

### 12.1 データ

- 既存人物に `imageAssetId: null` を補える
- 安全な `imageAssetId` を復元できる
- 不正な参照だけをnullへ戻し、人物位置と名前を維持する
- `character_pin` のmetadataを検証できる
- `item_image` の既存検証を維持する

### 12.2 保存

- 追加成功後だけ人物参照を更新する
- 変更成功時に旧人物画像アセットを削除する
- 変更失敗時に旧人物画像を維持する
- 削除確認だけでは削除しない
- 削除成功後だけ参照をnullへする
- 人物Aの操作が人物Bの画像参照を変更しない
- DBバージョン6のままである
- BlobをSaveSnapshotへ含めない

### 12.3 表示

DOMテスト基盤を新規導入せず、可能な範囲で純粋関数、キャッシュ、既存構造をテストする。

- 有効画像がある人物は画像表示を選ぶ
- 画像なし、欠損、owner不一致、kind不一致はmarkerへ戻る
- キャッシュが同じassetIdでURLを再生成しない
- assetId変更で旧URLをrevokeする
- 古い非同期結果を別人物または新画像へ適用しない
- 代理表示も同じ画像解決結果を使用する

### 12.4 既存機能

- 主人公とパートナーの地点移動を維持する
- 代理表示の居場所ダイアログを維持する
- パートナーの自律行動を維持する
- パートナー表示名を維持する
- アイテム個別画像の追加、変更、削除を維持する
- カテゴリ共通画像の三段フォールバックを維持する
- イベント、相談、保存復元テストを維持する

## 手動確認

1. 既存セーブで起動する。
2. 「設定」タブを開く。
3. 主人公へ画像を選び、プレビュー後に保存する。
4. パートナーへ別画像を選び、プレビュー後に保存する。
5. 「マップ」へ戻り、同じマップの二人が各画像で表示されることを確認する。
6. 片方を別マップへ移動させ、代理表示にその人物画像が出ることを確認する。
7. ページを再読込し、両画像と人物位置が残ることを確認する。
8. 一方の画像を変更し、もう一方が変わらないことを確認する。
9. 一方の画像を削除し、その人物だけmarkerへ戻ることを確認する。
10. パートナーの表示名、設定revision、台詞、現在地、イベント、花の相談結果、アイテム画像が残ることを確認する。
11. 自律行動を続け、再描画で画像が点滅、再読込、入替わりしないことを確認する。
12. 320px相当幅で横スクロールがないことを確認する。
