## 対象

Milestone 8B-4A：既存地点の背景上配置

## 目的

室内 `starter_house_interior` と庭 `starter_garden` に現在ある固定地点を、登録済み背景または仮背景へ合わせて配置し直し、保存できるようにする。

このMilestoneでは、既存地点のID、名前、種類、接続、移動ルールを維持したまま、表示座標だけをマップごとに調整する。

対象地点：

### 室内

- `kitchen` 台所
- `table` テーブル
- `sofa` ソファ
- `workbench` 作業台
- `entrance` 玄関

### 庭

- `front` 家の前
- `garden` 庭
- `shed` 物置

正確な既存locationIdはコード上の定義を優先する。上記と異なる場合、新しいIDを作らず、既存IDと表示名を使用する。

- 経路グラフ、隣接関係、移動速度、ゲート接続を変更しない
- 室内と庭の出入口接続を編集するUIを追加しない
- 家の外観ボタン、別マップ人物の代理表示位置を編集しない
- アイテムスロット、アイテム配置を追加しない
- 新しいマップの作成、複製、削除を追加しない
- 背景画像、人物画像、アイテム画像の追加、変更、削除を変更しない
- 背景画像の倍率、切抜き、表示位置を変更しない
- キャラクターピンの接地点、表示倍率、表示位置を変更しない

## 1. 地点配置データ

地点座標はピクセルではなく、0から1の相対値として保存する。

少なくとも次の意味を持つ型を用意する。

```ts
type RelativePoint = {
  x: number;
  y: number;
};

type LocationLayout = Record<string, RelativePoint>;
```

正確な型名とファイル分割は既存構造へ合わせてよい。

既存 `MapVisualState` または同等のマップ別安定データへ、後方互換な地点配置を追加する。

```ts
type MapVisualState = {
  saveSlotId: "main";
  mapId: "starter_house_interior" | "starter_garden";
  backgroundAssetId: string | null;
  locationLayout: LocationLayout;
  updatedAt: string;
};
```

ルール：

- 室内と庭の配置を独立して持つ
- 保存対象は、そのマップに実在する既存locationIdだけ
- 不明なlocationIdは無視する
- 地点が一件欠けている場合は、その地点だけプリセット座標へ戻す
- `x`、`y`のどちらかだけ不正な場合は、その成分だけプリセット座標へ戻す
- `NaN`、`Infinity`、文字列、範囲外の値を保存値として受理しない
- 安定データへCSS文字列、ピクセル値、DOM座標、Object URLを保存しない
- 一地点の不正値で、同じマップの他地点、もう一方のマップ、背景、人物、イベントを捨てない

## 2. 座標範囲と正規化

保存値は0から1の有限数とする。

UIでは百分率として表示してよい。

- 左端0、右端1
- 上端0、下端1
- 基本刻み0.01
- 永続化前に小数第2位相当へ正規化してよい

44px以上の地点操作をマップ枠内に保つため、編集UIから保存できる中心座標は原則0.05から0.95とする。

既存プリセット座標がこの範囲外にある場合は、既存値を壊さず表示し、初回編集時に安全な範囲へ正規化する。

純粋関数として少なくとも次を分離する。

- マップ定義と保存済み上書きから有効な地点座標を解決する
- 一地点の入力を検証、正規化する
- 一マップ分の壊れた保存値を地点単位、成分単位で部分復旧する
- 初期配置を既存プリセット定義から作る

プリセットマップ定義そのものを実行中に書き換えない。

## 3. 設定画面

既存「設定」画面の「マップ背景」で、室内と庭それぞれへ `地点を配置` または同等の操作を追加する。

背景画像が未登録でも、既存仮背景を使って編集できる。

### 3.1 編集開始

編集開始時は、現在保存されている有効配置を一時ドラフトへコピーする。

- 室内と庭のドラフトを独立させる
- 編集開始だけでは永続状態と実際のマップを変更しない
- 背景画像の選択中、保存中、削除確認中は同じマップの配置編集を開始しない
- 配置編集中は同じマップの背景変更、削除を開始しない

### 3.2 プレビュー

現在の3:4マップ枠と同じ比率、同じ背景表示を使う。

プレビューへ次を表示する。

- 現在の背景画像または仮背景
- 対象マップの全地点マーカー
- 選択中地点の明確な表示
- 選択中地点の名前
- 横位置と縦位置の現在値

実際のマップと同じ座標計算を使う。

プレビューには人物、イベント、家の外観、代理表示を必須としない。誤ってゲーム状態を操作しない読み取り専用表示とする。

### 3.3 操作

タッチ操作しやすい方法で、少なくとも次を提供する。

- 地点一覧または選択ボタン
- マーカーをタップして地点を選択
- 横位置のrange入力
- 縦位置のrange入力
- 現在値の百分率表示
- `この地点を初期位置に戻す`
- `全地点を初期配置に戻す`
- `この配置を保存`
- `キャンセル`

ドラッグ操作は追加してよいが、ドラッグだけを必須にしない。

一地点を動かしても、他地点のドラフトを上書きしない。

自律行動などの無関係なStore更新で、編集中のドラフト、選択地点、フォーカスを失わない。

### 3.4 保存とキャンセル

- 保存成功後だけStoreの安定状態と実際のマップへ反映する
- 保存失敗時は旧配置を維持し、ドラフトを残して再試行またはキャンセルできる
- キャンセル時は保存済み配置へ戻る
- 初期位置へ戻す操作はドラフトだけを更新し、保存操作で確定する
- 保存中は同じマップの二重操作を無効化する
- 成功、失敗を `aria-live` で通知する

## 4. 永続化

IndexedDBバージョン7と既存ストアを維持する。

地点配置は既存 `mapVisuals` レコードへ保存するか、同じストアを使う後方互換な同等方法とする。

- 新しいストアを追加しない
- 室内または庭の一件だけを一つのreadwrite transactionで更新する
- `backgroundAssetId` を維持する
- もう一方のマップレコードを変更しない
- transaction成功後だけメモリ状態へ反映する
- 保存失敗時は以前の配置と背景参照を維持する
- 既存DB7レコードに配置がなければプリセット座標を補う
- 通常のSaveSnapshotへ一時ドラフト、選択地点、DOM座標を含めない
- 安定した地点配置は既存の保存、復元、全体自動保存で失われないようにする

RepositoryまたはSaveCoordinatorに、マップ一件の配置を保存する専用処理を追加してよい。

全体リセットでは地点配置をプリセット座標へ戻す。背景画像、人物画像、アイテム画像に関する既存リセット仕様を維持する。

## 5. 実際のマップ描画

実際のマップでは、保存済み配置を既存マップ定義へ安全に重ねて使用する。

配置を反映する対象：

- 地点ボタン
- その地点にいる主人公とパートナーのピン
- 地点IDへ結び付くイベントマーカー
- 移動中に経由する地点の表示位置

維持するもの：

- 地点IDと表示名
- aria-label
- タップ領域44px以上
- 地点選択による主人公移動
- パートナーの自律移動
- 最短経路の地点ID列
- ゲート移動
- 背景、家の外観、イベント、人物、代理表示のレイヤー順
- キャラクターピンの接地点、倍率、画像位置

このMilestoneでは、家の外観ボタンと別マップ代理表示の配置座標を変更しない。

地点配置を変えても、経路グラフと論理現在地は変わらない。座標は表示と移動演出の位置にだけ使用する。

保存済み上書きから解決した一時的なMapDefinition相当を使用し、共有プリセット定義を破壊的に変更しない。

## 手動確認

1. 既存セーブで起動し、背景、人物画像、人物ピン表示設定が残っていることを確認する。
2. 「設定」の室内背景セクションから地点配置を開く。
3. 台所、テーブル、ソファ、作業台、玄関を一件ずつ選び、横位置と縦位置を変える。
4. 編集中はプレビューだけが変わり、実際のマップが変わらないことを確認する。
5. 保存し、室内マップの地点ボタンが背景へ合うことを確認する。
6. 主人公とパートナーを各地点へ動かし、人物ピンが地点へ追従することを確認する。
7. 庭の家の前、庭、物置を別の配置へ保存し、室内配置が変わらないことを確認する。
8. 「知らない芽」等の地点イベントが対応地点へ追従することを確認する。
9. 室内と庭を移動し、ゲート経路、家の外観ボタン、代理表示が従来どおり動くことを確認する。
10. ページを再読込し、両マップの配置が残ることを確認する。
11. 一地点を初期位置へ戻して保存できることを確認する。
12. 全地点を初期配置へ戻して保存できることを確認する。
13. 320px幅とiPhone縦画面で横スクロールせず操作できることを確認する。
14. 表示名、設定revision、現在地、背景、人物画像、人物ピン設定、イベント、花の相談結果、アイテム画像が残ることを確認する。
