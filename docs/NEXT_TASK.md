# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 4：パートナーが暮らし始める

## 目的

公開プリセットパートナー「コーディ」が、端末内のJavaScriptだけで次の行動を自分で選び、既存の移動基盤を使って必要な地点へ移動し、短時間その行動を行うようにする。

このMilestoneでは、最初の小さな自律生活を完成させる。

- 性格と好みにより、選びやすい行動へ偏りが生まれる
- 重み付き抽選により、毎回同じ結果へ固定されない
- 直近行動へのペナルティにより、同じ行動だけを繰り返しにくい
- `join_user` は候補の一つであり、主人公へ常に追従しない
- 時間帯、天気、体力、気分、イベント、実アイテムはまだ扱わない
- LLM APIやパートナーチャットへ問い合わせない

## 基本ルール

- 自律行動するのはコーディだけとする。
- 主人公は引き続きユーザー操作だけで移動する。
- 通常画面から、ユーザーがコーディの行動を直接命令する機能は追加しない。
- コーディの自律移動にはMilestone 2の経路探索と段階移動を再利用する。
- 接続されていない地点へ瞬間移動させない。
- コーディが自律移動中または行動中は、新しい自律行動を重ねない。
- アプリを閉じている間の行動進行や、経過時間の追いつき処理は行わない。
- ページ再読込後は、保存済みの現在地から新しい自律生活を開始する。途中だった移動、行動、タイマーは復元しない。

## 実装する

### 1. 行動IDと行動定義

今回実装する行動IDは次の六つだけとする。

```ts
type ActionId =
  | "rest"
  | "cook"
  | "garden"
  | "craft"
  | "join_user"
  | "inspect_item";
```

行動定義はデータとしてまとめ、少なくとも次を持つ。

```ts
type ActionDefinition = {
  actionId: ActionId;
  label: string;
  baseScore: number;
  durationMs: number;
  lineIds: string[];
};
```

今回の初期値は次を基準とする。秒数は試遊後に調整可能なバランス値であり、定数へまとめる。

| actionId | 表示名 | 主な実行地点 | baseScore | durationMs目安 |
| --- | --- | --- | ---: | ---: |
| `rest` | 休憩する | ソファ | 32 | 12000 |
| `cook` | 料理する | 台所 | 30 | 14000 |
| `garden` | 庭仕事をする | 庭 | 30 | 16000 |
| `craft` | 工作する | 作業台 | 30 | 15000 |
| `join_user` | 主人公のそばで過ごす | 行動決定時の主人公の現在地 | 36 | 10000 |
| `inspect_item` | 周囲を調べる | 作業台、物置、テーブルのうち最寄り | 28 | 9000 |

`inspect_item`というIDは将来のアイテム機能と接続するため維持する。ただし、このMilestoneではアイテムデータを作らず、作業台、物置、テーブル付近の道具や小物を見回す仮行動として扱う。

### 2. コーディの初期ゲーム用プロフィール

製品仕様の公開プリセット値を、行動選択用データとして追加する。

```ts
const codyPersonality = {
  initiative: 72,
  curiosity: 82,
  sociability: 58,
  caretaking: 78,
  affection: 64,
  tidiness: 70,
  patience: 76,
  moodVolatility: 30,
  solitudePreference: 47,
  userPriority: 80,
  adventurousness: 56,
  caution: 62
};
```

好みの初期値：

```ts
preferredActionIds = ["cook", "garden", "craft", "inspect_item"];
dislikedActionIds = [];
```

このデータはJavaScriptの行動選択にのみ使用する。コーディの人格全文、関係性、会話履歴は保存しない。

### 3. 実行可能候補と目的地

現在のマップ、地点、主人公とコーディの位置から、実行可能な行動候補を作る純粋関数を追加する。

各行動は一つの候補として扱う。複数の実行地点を持つ`inspect_item`を地点数だけ複製し、抽選確率を不当に増やさない。

目的地の決め方：

- `rest`：室内の`sofa`
- `cook`：室内の`kitchen`
- `garden`：庭の`garden`
- `craft`：室内の`workbench`
- `join_user`：行動決定時点の主人公の`mapId`と`locationId`
- `inspect_item`：`workbench`、`shed`、`table`のうち、既存グラフ上でコーディから最短の地点。距離が同じ場合はこの記載順を優先する

候補作成時に、目的地まで有効な経路がない行動は除外する。

コーディがすでに目的地にいる場合、その行動は候補から除外せず、移動を省略してすぐ行動を開始できる。

`join_user`の目的地は決定時のスナップショットとする。主人公がその後移動しても、コーディは途中で追跡先を変更しない。次の行動選択時に改めて現在状態を見る。

### 4. 点数計算

候補ごとに点数内訳を作る純粋関数を追加する。

```ts
type ActionScoreBreakdown = {
  actionId: ActionId;
  destination: LocationRef;
  base: number;
  personality: number;
  preference: number;
  repetition: number;
  randomJitter: number;
  total: number;
  weight: number;
};
```

#### 性格補正

関連パラメータの平均値を使う。

- `rest`：`patience`、`solitudePreference`
- `cook`：`caretaking`、`tidiness`
- `garden`：`curiosity`、`patience`
- `craft`：`initiative`、`curiosity`、`tidiness`
- `join_user`：`sociability`、`affection`、`userPriority`
- `inspect_item`：`curiosity`、`caution`

基準式：

```ts
normalizePersonality(average) = clamp((average - 50) / 5, -10, 10);
```

`join_user`だけは主人公への常時追従を避けるため、この値へ`0.75`を掛ける。

丸め方は一貫していればよい。計算は純粋関数へ分離する。

#### 好み補正

- preferred：`+20`
- disliked：`-20`
- どちらでもない：`0`

#### 反復ペナルティ

`recentActionIds`は新しい順に最大5件保持する。

同じ行動が次の位置にある場合、ペナルティを加える。

| 履歴位置 | ペナルティ |
| --- | ---: |
| 直前 | -32 |
| 2件前 | -18 |
| 3件前 | -10 |
| 4件前 | -5 |
| 5件前 | -2 |

同じ行動が複数位置にある場合は合計する。

直近二件が同じ行動で、他に有効な候補が一つ以上ある場合、その行動は次の一回だけ抽選対象から外す。反復ペナルティを主としつつ、三連続だけを安全に防ぐ。

#### 小さな乱数

候補ごとに`-2`から`+2`の小さな乱数補正を加える。

テスト可能にするため、乱数源を引数またはinterfaceとして注入できるようにする。テストで`Math.random`へ直接依存しない。

#### 合計と重み

```ts
total = base + personality + preference + repetition + randomJitter;
weight = Math.max(1, round(total));
```

### 5. 重み付き抽選

有効候補から、`weight`に比例する重み付き抽選を行う純粋関数を追加する。

- 常に最高点だけを選ぶ方式にしない
- 全候補の点数内訳を返す
- 選ばれた候補を識別できるようにする
- 乱数源を注入し、決定的な自動テストを可能にする
- 候補がない場合は失敗として返し、瞬間移動や例外終了を起こさない

### 6. 自律行動状態

`AppState`へコーディの自律生活を表す状態を追加する。

```ts
type PartnerActivityPhase = "idle" | "moving" | "acting";

type PartnerActivityState = {
  enabled: boolean;
  phase: PartnerActivityPhase;
  actionId: ActionId | null;
  destination: LocationRef | null;
  lineId: string | null;
  recentActionIds: ActionId[];
  lastDecision: ActionDecisionDebug | null;
};
```

最低限のルール：

- 初期状態は`enabled: true`、`phase: "idle"`
- `recentActionIds`は最大5件
- `lastDecision`は開発者表示用であり、保存しない
- 現在の行動、台詞、タイマー、移動途中状態は保存しない
- ページ再読込後は`idle`から再開する

`ActionDecisionDebug`には、全候補の点数内訳、選択された行動、決定時刻または連番を保持してよい。

### 7. 自律行動の進行

タイマー管理と選択ロジックをStoreへ混ぜ込みすぎず、専用のcontrollerまたはcoordinatorへ分離する。

基本の流れ：

1. アプリ起動と復元が完了する
2. 自律行動が有効で、コーディが移動中でも行動中でもないことを確認する
3. 約1200ms後に行動候補を作り、点数計算と抽選を行う
4. 選択結果と点数内訳を状態へ記録する
5. 目的地と現在地が異なる場合、既存の移動処理でコーディを移動させる
6. 目的地へ到着したら行動を開始する
7. 定義された`durationMs`の間、行動中として表示する
8. 完了時に行動IDを`recentActionIds`の先頭へ追加し、最大5件へ切り詰める
9. 状態を`idle`へ戻し、約1200ms後に次の選択を行う

行動決定待ちの時間は定数へまとめる。

既存のキャラクター移動タイマーを再利用または共通化し、自律移動専用の別経路更新ロジックを複製しない。

目的地への到着を検知できるよう、移動実行側は必要に応じて完了callbackまたは同等の仕組みを持てる。

経路が途中で無効になった場合：

- 現在地で安全に停止する
- 自律行動を`idle`へ戻す
- 開発者向けに原因を確認できる
- 少し待ってから次の行動を選べる
- 瞬間移動しない

### 8. タイマー、重複防止、リセット

- 自律行動の決定タイマーは一つだけにする
- コーディの行動時間タイマーは一つだけにする
- コーディの移動タイマーを重複させない
- 再描画のたびにタイマーを増やさない
- `document.hidden`中は、新しい行動決定を開始しない
- 非表示中の経過時間を使って複数行動を一括処理しない
- 表示へ戻った時、自律行動が有効かつidleなら一件だけ次の決定を予約する

「初期状態へ戻す」では次を行う。

- 主人公とコーディの移動タイマーを停止
- 自律行動の決定タイマーと行動時間タイマーを停止
- コーディの現在行動を解除
- `recentActionIds`を空へ戻す
- Storeを初期状態へ戻す
- 初期状態をIndexedDBへ保存
- 自律行動を一重に再開する

### 9. 開発者パネルでの一時停止と確認

開発者パネルへ次を追加する。

- 自律行動の有効／一時停止状態
- コーディのphase
- 現在の行動名
- 目的地
- 直近5行動
- 「自律行動を一時停止」または「自律行動を再開」ボタン
- idleかつ有効な時だけ使える「次の行動を今すぐ選ぶ」ボタン
- 最後の行動決定の点数内訳

点数内訳では候補ごとに最低限、次を表示する。

- 行動名
- 目的地
- base
- personality
- preference
- repetition
- randomJitter
- total
- weight
- 選択された候補

通常画面へ点数を表示しない。

既存のコーディ移動先selectは維持する。ただし、自律行動が有効な間は手動移動を無効にし、説明を表示する。自律行動を一時停止した時だけ、コーディを開発者操作で移動できる。

一時停止時：

- 保留中の自律決定タイマーを止める
- 行動中なら行動時間タイマーを止め、行動を解除する
- 自律移動中なら、最後に到着済みの地点で停止して移動状態を解除する
- 途中の行動を`recentActionIds`へ追加しない

再開時：

- 状態をidleへ整える
- 次の行動決定を一件だけ予約する

### 10. 短い登録台詞

行動ごとに短い登録台詞を二つ以上用意する。

例：

```ts
rest: [
  "少しひと休みしようかな。",
  "ここで息を整えておくよ。"
]

cook: [
  "何か簡単なものを作っておこう。",
  "台所を借りるね。いい匂いにできるかな。"
]

garden: [
  "葉の様子を見てくるよ。",
  "昨日と少し違う気がするんだ。"
]

craft: [
  "この辺り、少し手を入れられそうだ。",
  "道具の調子を見ておこう。"
]

join_user: [
  "ちょっとそばにいてもいい？",
  "同じところで過ごそうかな。"
]

inspect_item: [
  "気になるものがあるんだ。少し見てみるよ。",
  "この辺り、何か変わっていないかな。"
]
```

台詞は固定データであり、LLM生成しない。

同じ台詞を連続で選ばない。台詞選択の乱数も注入可能にするか、純粋関数としてテストできる形にする。

このMilestoneでは台詞編集UI、パートナー設定取込、会話履歴を追加しない。

### 11. 通常画面の表示

「現在の様子」を状態連動にする。

例：

```text
主人公はテーブルにいます。
コーディは庭へ移動中です。
```

```text
コーディは庭で庭仕事をしています。
「葉の様子を見てくるよ。」
```

コーディが行動中で、現在表示中のマップにいる場合、Cピンの近くへ短い行動名のテキストバッジを表示してよい。

- バッジは画像を必須にしない
- 色だけで意味を伝えない
- 読み上げ名を持たせる
- 小画面で地点ボタンを塞がない
- `prefers-reduced-motion`に反する常時アニメーションを追加しない

既存の`aria-live`領域で、次を読み上げ可能にする。

- コーディが行動先へ移動を開始した
- 現在地と目的地
- 行動を開始した地点と行動名
- 行動を終えたこと

### 12. 保存

Milestone 3の保存へ、反復防止に必要な`recentActionIds`だけを追加する。

`worldStates`レコードまたは同等の安定した保存場所へ、次を追加してよい。

```ts
recentPartnerActionIds: ActionId[];
```

保存する：

- 既存の`viewedMapId`
- 主人公とコーディの現在地
- `recentActionIds`の有効な先頭5件

保存しない：

- `enabled`
- `phase`
- 現在の`actionId`
- 現在の`destination`
- `lineId`
- `lastDecision`
- 行動タイマー
- 自律決定タイマー
- 移動タイマー

復元ルール：

- 既存のMilestone 3セーブに履歴がなくても起動できる
- 未知の行動IDは無視する
- 最大5件へ切り詰める
- 読込後は`enabled: true`、`phase: "idle"`
- 現在行動とタイマーは復元しない
- DBのobject store構成は変えないため、不要なDBバージョン更新を行わない

`recentActionIds`が更新された時とリセット時は、自動保存対象とする。

### 13. テスト

最低限、次を自動テストする。

#### 候補と目的地

- 六つの行動定義が存在する
- 各固定行動が正しい地点を目的地にする
- `join_user`が決定時点の主人公の位置を目的地にする
- 主人公が後から移動しても、決定済み`join_user`の目的地を変更しない
- `inspect_item`が複数地点分の抽選枠へ増殖せず、最寄り地点を一つ選ぶ
- 経路がない行動を候補から除外する
- 目的地と同じ場所でも行動候補にできる

#### 点数と抽選

- baseScoreが内訳へ入る
- 性格補正が関連パラメータから計算される
- preferredへ`+20`、dislikedへ`-20`が入る
- 直近5行動の位置に応じた反復ペナルティが入る
- 直近二件が同じ場合、代替候補があれば三連続を防ぐ
- 乱数源を固定すると同じ選択結果になる
- 重み付き抽選が最高点固定ではない
- 点数内訳と選択候補を返す

#### 進行

- 目的地が異なる場合、既存移動基盤を使って移動後に行動を開始する
- 目的地が同じ場合、移動せず行動を開始する
- 行動完了後に`recentActionIds`へ追加し最大5件にする
- 行動中に次の自律行動を重ねない
- 一時停止で決定、行動、コーディ移動のタイマーを止める
- 再開で次の決定を一件だけ予約する
- リセット後に古いタイマーが状態を書き換えない
- 非表示中に複数行動をまとめて処理しない

#### 表示と保存

- 現在の様子がmoving、acting、idleを区別する
- 行動開始と完了が読み上げ用メッセージへ反映される
- 同じ台詞を連続で選ばない
- 保存スナップショットに`recentActionIds`が入り、現在行動やタイマーは入らない
- 履歴なしの旧セーブを復元できる
- 未知の行動IDを無視し、有効な先頭5件だけ復元する
- リセット後の空履歴を保存する

乱数、時刻、タイマーは注入可能な境界を用意し、実時間待ちへ依存する不安定なテストを作らない。

既存の移動、保存、復旧テストを維持する。

## 完成条件

- コーディが六つの行動から自分で候補を作り、重み付き抽選で一つ選ぶ
- 性格、好み、直近行動が点数へ反映される
- 同じ行動だけを繰り返し続けない
- `join_user`が常時強制されず、主人公へ必ず追従しない
- 必要な地点へ既存経路を通って移動し、到着後に行動する
- 接続されていない地点へ飛ばない
- 行動中の状態と短い登録台詞が通常画面で分かる
- 行動開始と完了が読み上げ可能である
- 開発者パネルで最後の点数内訳を確認できる
- 開発者パネルから自律行動を一時停止、再開できる
- 自律行動が有効な間、開発者の手動コーディ移動を重ねない
- ページ再読込後は保存済み地点からidleで再開する
- 直近5行動が保存され、反復防止へ利用される
- リセットと一時停止後に古いタイマーが残らない
- 既存の主人公移動、コーディ移動、代理表示、IndexedDB保存を維持する
- typecheck、test、buildが成功する
- GitHub ActionsのCIが成功する
- 範囲外の時間、天気、体力、イベント、実アイテム、オフライン進行を追加していない
