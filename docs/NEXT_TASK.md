# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-3C：接地点・表示位置・表示倍率の調整

## 目的

Milestone 8B-3Aで登録できるようにした主人公とパートナーのキャラクターピン画像を、Milestone 8B-3Bの室内・庭背景上で自然に見えるよう、人物ごとに最小限調整できるようにする。

対象は次だけとする。

- 主人公 `user`
- パートナー `cody`
- マップ上のキャラクターピン
- 別マップ人物の代理表示について、画像の見切れを避けるための表示位置

接地点は地点データが示す座標と画像上の足元を結び付ける表示設定である。調整しても人物の `mapId`、`locationId`、地点座標、経路は変更しない。

画像がない、削除した、壊れている、参照が不正、読込に失敗した、または調整値が不正な場合も、既存の文字マーカーと安全な初期表示で移動、自律行動、イベント、アイテム、相談を継続する。

## このMilestoneで変えないもの

- マップID、マップ種別、地点ID、地点座標を変更しない
- 経路、ゲート、代理表示の配置座標を変更しない
- 人物の現在地、表示名、画像アセット参照を調整操作で変更しない
- 室内背景、庭背景の画像、表示位置、倍率を変更しない
- 画像Blobそのものを切抜き、圧縮、回転、色補正しない
- キャラクター画像の追加、変更、確認付き削除の既存挙動を変更しない
- ユーザー作成マップ、地点編集、アイテム配置を追加しない
- 外部通信、画像生成API、クラウド保存を追加しない

地点マッピング、出入口、代理表示の配置座標、アイテムスロット、カスタムマップはMilestone 8B-4へ分ける。

## 1. 表示調整データ

キャラクターごとに、少なくとも次の意味を持つ表示設定を保存する。

```ts
type CharacterPinVisual = {
  anchorX: number;
  anchorY: number;
  scale: number;
  objectPositionX: number;
  objectPositionY: number;
};
```

正確な型名、保存単位、ファイル分割は既存構造へ合わせてよい。値の意味は次で固定する。

- `anchorX`：画像枠の左端を0、右端を100とした接地点の横位置
- `anchorY`：画像枠の上端を0、下端を100とした接地点の縦位置
- `scale`：既存ピンサイズを1とした表示倍率
- `objectPositionX`：切抜き枠内で見せる画像位置の横成分。左端0、右端100
- `objectPositionY`：切抜き枠内で見せる画像位置の縦成分。上端0、下端100

初期値：

```ts
{
  anchorX: 50,
  anchorY: 100,
  scale: 1,
  objectPositionX: 50,
  objectPositionY: 50
}
```

ルール：

- 主人公とパートナーの値を独立して持つ
- 接地点の範囲は0から100
- 表示倍率の範囲は0.5から2
- 表示位置の範囲は0から100
- `NaN`、`Infinity`、文字列、範囲外の値は、その項目だけ初期値へ戻す
- 一人の不正値で、もう一人、画像参照、現在地、ゲーム本体を捨てない
- CSS文字列、Object URL、画面座標を安定状態として保存しない

表示倍率の入力刻みは0.05、接地点と表示位置は整数を基本とする。永続化前にも値を正規化し、UIだけの制限へ依存しない。

## 2. 設定画面

既存「設定」画面の「ふたりの見た目」で、主人公とパートナーそれぞれに「表示を調整」または同等の操作を追加する。

画像未登録でも文字マーカーの既定表示は維持する。画像固有の調整操作は、画像が登録され正常に読み込める場合だけ有効にする。

### 2.1 プレビュー

- 現在の3:4マップ枠に相当するプレビューを表示する
- 地点を示す固定ガイドと接地点を示すガイドを表示する
- 実際のマップピンと同じ計算で接地点、表示倍率、表示位置を反映する
- 室内または庭の既存仮背景を使い、背景アセットの変更機能は混ぜない
- プレビュー操作で人物の現在地や表示マップを変更しない

### 2.2 操作

各人物について次を扱う。

- 接地点の左右
- 接地点の上下
- 表示倍率
- 画像の表示位置の左右
- 画像の表示位置の上下
- `初期値に戻す`
- `この表示設定を保存`
- `キャンセル`

範囲入力と数値表示、または同等にタッチ操作しやすいUIを使う。画像上のドラッグ操作だけを必須にしない。

- 主要操作は44px以上
- 入力文字は16px以上
- 現在値をテキストでも確認できる
- 色だけで接地点を示さない
- 320px幅で横スクロールを発生させない
- 編集中は即時プレビューするが、保存操作までは永続状態へ反映しない
- 保存中は同じ人物の二重操作を無効化する
- 一人の編集中に、もう一人のドラフトを上書きしない

### 2.3 保存とキャンセル

- 保存成功後だけStoreの安定状態とマップ表示へ反映する
- 保存失敗時は既存設定を維持し、編集値を残して再試行またはキャンセルできる
- キャンセル時は保存済み設定へ戻る
- 初期値へ戻す操作もプレビューだけを更新し、保存操作で確定する
- 成功、失敗を `aria-live` で通知する

## 3. 永続化

IndexedDBバージョン7と既存ストアを維持し、新しいストアや依存ライブラリを追加しない。

表示設定は既存 `characters` レコードへ後方互換な任意データとして保存するか、既存構造に沿う同等の方法を使う。

- DBバージョンを8へ上げない
- 既存レコードに表示設定がなければ初期値を補う
- 主人公またはパートナーの一件だけを更新する
- 保存は一つのreadwrite transactionで完了する
- transaction成功後だけメモリ状態へ反映する
- 画像メタデータとBlobは書き換えない
- `imageAssetId`、`mapId`、`locationId`、名前、markerを維持する
- 通常のSaveSnapshotへ一時ドラフトやCSS計算値を含めない
- 安定した表示設定は既存の保存・復元経路でも失われないようにする

全体リセットでは表示設定を初期値へ戻す。人物画像、背景画像、アイテム画像に関する既存リセット仕様は維持する。

## 4. マップ描画

### 4.1 キャラクターピン

地点座標はこれまでどおりマップ・地点データから導出する。その座標を接地点として、画像枠を配置する。

- `anchorX` と `anchorY` は画像枠のどの点を地点座標へ合わせるかだけを決める
- `scale` は画像を持つ人物ピンの表示寸法だけへ適用する
- `objectPositionX` と `objectPositionY` は既存 `object-fit: cover` の見せる位置へ適用する
- 設定値から安全なCSS値を組み立て、保存済み文字列をそのままstyleへ渡さない
- 二人が同じ地点にいる場合も、それぞれの設定を独立して使う
- 地点ボタン、イベント、背景、代理表示の既存レイヤー順を維持する
- 調整によってマップ枠の横スクロールを発生させない

文字マーカーでは既存サイズと中央表示を維持し、画像用設定によって文字を見切れさせない。

### 4.2 代理表示

代理表示の配置座標、ボタンサイズ、ラベル、操作は変更しない。

- 登録画像には `objectPositionX` と `objectPositionY` を反映する
- 代理表示へマップピン用の `scale` と接地点をそのまま適用しない
- 代理表示を44px未満の操作領域にしない
- 画像なし、読込失敗時は既存文字markerへ戻す

これは代理表示の見切れ確認に必要な最小対応であり、代理表示専用の接地点、倍率、配置座標は追加しない。

## 5. 画像取得とライフサイクル

既存のキャラクターピン画像キャッシュ、世代照合、Object URL管理を維持する。

- 表示設定の編集や保存だけでBlobを再取得しない
- 同じ `imageAssetId` のObject URLを再利用する
- 無関係な自律行動更新でObject URLを再生成しない
- 画像変更、削除、全体リセット、`pagehide` の既存revokeを壊さない
- Safariのbfcacheからの `pageshow.persisted` で安定参照から画像を再取得できる
- 古い画像取得結果で現在の表示設定や別人物を上書きしない

## 6. アクセシビリティとモバイル

- iPhone Safariの縦画面を最優先する
- 範囲入力だけに依存せず、ラベルと現在値を関連付ける
- 接地点、表示位置、倍率の意味を日本語で説明する
- キーボードとタッチの両方で操作できる
- フォーカス表示を消さない
- 保存、失敗、初期値復帰を読み上げ可能にする
- `prefers-reduced-motion` を損なうアニメーションを追加しない
- プレビュー更新で不要なフォーカス移動を起こさない

## 7. セキュリティとプライバシー

- 外部通信を追加しない
- 画像、表示設定、現在地をパートナーチャットや相談プロンプトへ含めない
- 動的なラベルと数値は `textContent` または安全なDOM APIで描画する
- `innerHTML`、`eval`、`Function`、動的importを使用しない
- CSSへ反映する値は検証済みの有限数から生成する

## 8. このMilestoneで扱わないもの

- 代理表示専用の画像、接地点、倍率、配置座標
- 地点の追加、削除、移動
- 出入口接続編集
- アイテムスロット
- カスタムマップ
- 画像Blobの切抜き、圧縮、回転、色補正
- 複数の人物画像、衣装、表情差分
- 思い出CG、バックアップ、PWA
- 本番背景、人物、アイテム素材制作

## 手動確認

1. 既存セーブで起動し、人物画像と室内・庭背景が残っていることを確認する。
2. 「設定」の「ふたりの見た目」を開く。
3. 主人公の表示調整を開き、接地点、表示倍率、表示位置を変える。
4. プレビューだけが更新され、保存前のマップと永続状態が変わらないことを確認する。
5. 保存し、室内と庭の地点で主人公画像の足元、大きさ、見切れを確認する。
6. パートナーへ別の値を保存し、主人公の設定が変わらないことを確認する。
7. 二人を同じ地点へ移動し、それぞれの設定が反映されることを確認する。
8. 一人を別マップへ移動し、代理表示の配置と操作を保ったまま画像位置が反映されることを確認する。
9. ページを再読込し、両方の設定が残ることを確認する。
10. 初期値に戻して保存できることを確認する。
11. 人物画像を削除し、文字markerへ戻って移動と代理表示を続けられることを確認する。
12. 320px幅とiPhone縦画面で横スクロールせず操作できることを確認する。
13. 表示名、設定revision、現在地、背景、イベント、花の相談結果、アイテム画像が残ることを確認する。
