# 次の実装タスク

この文書には、Codexへ渡す依頼文を何度も読み返さずに済むよう、現在実装する一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-4D-2：カスタム地点と地点タイプ

## 目的

Milestone 8B-4D-1で保存できるようになった室内と庭のカスタムマップ下書きへ、カスタム地点を追加する。

ユーザーは下書きごとに1件から8件までの地点を持ち、地点名、地点タイプ、背景上の相対座標を追加、編集、削除し、明示保存できる。

このMilestoneでは下書きデータと下書きプレビューだけを変更する。通常マップ、主人公とパートナーの現在地、経路、自律行動、イベント、出入口、代理位置、アイテムスロットへはまだ反映しない。

## このMilestoneで変えないもの

- runtimeの `MapId` unionを変更しない
- 実行マップは `starter_house_interior` と `starter_garden` の二件を維持する
- 三枚目以降の実行マップを追加しない
- 表示中マップ、主人公とパートナーの `mapId`、`locationId` を変更しない
- 現在の通常マップの地点ID、地点名、地点タイプ、位置、接続を変更しない
- 現在の出入口、代理位置、庭の家の外観位置を変更しない
- 現在の基本アイテムスロットの位置と割当を変更しない
- 自律行動候補、行動重み、固定台詞、イベント、最短経路、移動速度を変更しない
- 現在の背景画像を複製、移動、所有者変更しない
- 新しい画像アップロード、画像形式、画像上限、Object URL生成経路を追加しない
- IndexedDBバージョンを9へ上げない
- 新しいストア、外部依存、外部通信、API接続を追加しない

## 1. 対象となる下書き

対象は既存 `customMapDrafts` ストアに保存された次の二枠だけとする。

```ts
type CustomMapTargetId =
  | "starter_house_interior"
  | "starter_garden";
```

- 室内枠と庭枠へ一件ずつまで下書きを持つ既存仕様を維持する
- 保存済み下書きがない枠では、先にMilestone 8B-4D-1の下書き作成を案内する
- 地点編集だけを理由に下書きを暗黙作成しない
- 下書き名、`status: "draft"`、`createdAt`を維持する
- 地点保存時は`updatedAt`だけを更新する

## 2. 安定データ

既存の `CustomMapDraft` または同等のレコードへ、次の意味を持つ地点配列を後方互換に追加する。

```ts
type CustomLocationTypeId =
  | "general"
  | "cooking"
  | "dining"
  | "rest"
  | "work"
  | "nature"
  | "storage";

type CustomMapLocation = {
  locationId: string;
  label: string;
  locationTypeId: CustomLocationTypeId;
  position: {
    x: number;
    y: number;
  };
};

type CustomMapDraft = {
  saveSlotId: "main";
  targetMapId: CustomMapTargetId;
  name: string;
  status: "draft";
  locations: CustomMapLocation[];
  createdAt: string;
  updatedAt: string;
};
```

正確な型名、ファイル名、関数分割は既存構造へ合わせてよい。配列順は設定画面の地点一覧と安定した復旧順序に使用する。

保存しないもの：

- 選択中の地点ID
- 編集画面の開閉状態
- 削除確認状態
- 入力フォーカス、スクロール位置
- DOM座標、CSS文字列、ピクセル値、Object URL
- `connectedLocationIds`
- gateway、代理位置、家の外観位置
- アイテムスロット
- 通常マップへ反映済みかを示す状態

## 3. 地点数

一つの下書きにつき、保存できる地点は1件以上8件以下とする。

- 1件未満の保存を許可しない
- 8件を超える追加操作を無効化し、短い日本語で上限を知らせる
- 保存値が8件を超える場合は、安定した配列順で最初の8件だけを復元する
- 検証後に有効な地点が0件になった場合は、対象枠の現在地点から初期地点を作り直す
- 最後の1地点を削除する操作は無効化し、「地点は一つ以上必要です」と知らせる

地点数は室内と庭で独立する。二枠を合わせた上限ではない。

## 4. locationId

`locationId`はゲームが生成、維持する安定IDであり、ユーザー入力項目にしない。

受理規則：

- 文字列である
- 1文字以上64文字以下である
- 半角小文字英数字、`_`、`-`だけを使う
- 先頭は半角小文字英数字である
- 同じ下書き内で重複しない

推奨する安全形式：

```text
custom_<UUID相当の一意部分>
```

- `crypto.randomUUID()`を利用できる場合は利用してよい
- 生成値をユーザーへ編集させない
- 新規追加ごとに新しいIDを作り、削除済みIDを意図的に再利用しない
- 重複IDが保存されている場合、配列順で最初の地点だけを維持し、後続を除外する
- 不正IDの地点はその一件だけを除外し、他地点と下書き名を捨てない

既存通常マップから初期地点を作る場合は、既存 `locationId` が上記規則を満たし、対象下書き内で一意ならそのIDを維持してよい。

## 5. 地点名

地点名はユーザーが編集する表示名である。

- 文字列だけを受理する
- 前後のUnicode空白を除去する
- 1文字以上24文字以下とする
- 制御文字を受理しない
- 同じ下書き内で同名を許可する
- 空、型違い、制御文字、上限超過の場合は配列順に応じた `地点1`、`地点2` 等へ戻す
- 動的な地点名は `textContent` または同等の安全なDOM APIで描画する

地点名の変更で `locationId` を変更しない。

新規地点の初期名は、既存名と重ならない最小の番号を使う。

例：

```text
新しい地点1
新しい地点2
```

## 6. 地点タイプ

地点タイプは次の7種類へ固定する。

| ID | 表示名 | 標準タグ |
|---|---|---|
| `general` | 汎用 | なし |
| `cooking` | 料理 | `cooking` |
| `dining` | 食卓 | `living` |
| `rest` | 休憩 | `rest` |
| `work` | 作業 | `work` |
| `nature` | 自然 | `nature` |
| `storage` | 収納 | `storage` |

- 保存値は上記IDだけを受理する
- 不明値、空、型違いは `general` へ戻す
- タイプIDから標準タグを返す純粋関数を用意する
- 表示名からタイプIDを推測しない
- アイテムカテゴリを地点タイプとして流用しない
- gatewayは地点タイプに含めない。出入口はMilestone 8B-4D-3で既存地点を選んで設定する
- このMilestoneではタイプを自律行動やイベントへまだ反映しない

現在通常マップから初期地点を作る場合は、既存 `locationTags` を次の優先順でタイプへ変換する。

1. `cooking` → `cooking`
2. `living` → `dining`
3. `rest` → `rest`
4. `work` → `work`
5. `nature` → `nature`
6. `storage` → `storage`
7. それ以外、`gateway`だけ → `general`

## 7. 相対座標

地点位置は3:4プレビュー内の0から1の相対座標で保存する。

- `x`は左端0、右端1
- `y`は上端0、下端1
- 有限数だけを受理する
- `NaN`、`Infinity`、文字列、範囲外を受理しない
- `x`、`y`の片方だけ不正な場合、その成分だけ安全な初期値へ戻す
- 永続化前に小数第2位相当へ正規化してよい
- UIの基本刻みは0.01
- 44px以上の地点マーカーを枠内に保つため、編集UIで指定できる中心位置は原則0.05から0.95とする

新規地点の初期位置は次の候補を順に使い、既存地点と重なりにくい最初の候補を選ぶ。

```ts
[
  { x: 0.50, y: 0.50 },
  { x: 0.25, y: 0.25 },
  { x: 0.75, y: 0.25 },
  { x: 0.25, y: 0.70 },
  { x: 0.75, y: 0.70 },
  { x: 0.50, y: 0.20 },
  { x: 0.15, y: 0.50 },
  { x: 0.85, y: 0.50 }
]
```

候補選択の正確な距離判定は実装仕様としてよい。候補がすべて使用済みでも追加を拒否せず、候補列から安定して一件を選び、ユーザーがrange入力で調整できるようにする。

## 8. 既存DB8下書きの初期地点

Milestone 8B-4D-1で保存された既存下書きは `locations` を持たない。

その場合、対象枠の現在の通常マップ定義と、Milestone 8B-4Aで保存された現在の地点配置から、メモリ上の初期地点を作る。

- 室内は現在の室内地点を初期地点にする
- 庭は現在の庭地点を初期地点にする
- 現在の地点名を `label` に使う
- 現在の有効な `locationId` を維持する
- 現在の `locationTags` を固定規則で地点タイプへ変換する
- 現在の保存済み相対座標を使う
- 初期地点の生成だけではIndexedDBへ書き込まない
- ユーザーが「地点設定を保存」した時に初めて `locations` を下書きレコードへ保存する

一度 `locations` を保存した下書きは、その後に通常マップの地点配置を変更しても自動追従しない。カスタム地点は下書きの独立データとして維持する。

保存値に `locations` が存在するが、有効地点が0件になった場合も同じ初期地点生成へ戻す。

## 9. 地点間接続のMVP方針

このMilestoneでは地点間接続の編集UIと `connectedLocationIds` を追加しない。

カスタムマップを通常マップへ反映するMilestone 8B-4D-4では、同じマップ内の全カスタム地点を相互に双方向接続する完全グラフとして解決する。

理由：

- MVPに複雑なマップエディターを追加しない
- 一方向接続や孤立地点による移動不能を避ける
- 地点配置と移動経路演出を分離する

この方針は、将来の中継点、折れ線動線、接続線編集を現在のMilestoneへ追加するものではない。

## 10. 設定画面

既存の `カスタムマップ下書き` 区画へ、保存済み下書きごとの `地点を編集` または同等の操作を追加する。

下書きがない場合は地点編集を表示せず、先に下書きを作る案内を出す。

一度に編集する対象は室内または庭の一件だけとする。

編集開始時：

- 保存済み下書きの有効地点を一時ドラフトへコピーする
- `locations` がない場合は現在の通常マップ地点から初期地点を作る
- 最初の地点を選択状態にする
- 保存済み下書きと通常マップを変更しない
- 背景変更、通常地点配置、出入口、アイテムスロット等の別エディターと同時編集させない

3:4プレビューに表示する：

- 現在登録されている対象枠の背景画像
- 背景がない、または読込失敗時の既存仮背景
- 編集中のカスタム地点マーカー
- 各地点名
- 選択中地点を色だけに依存しない表示
- 現在の地点数と上限8件
- 下書き名と室内／庭の種別
- 通常マップへ未反映であること

プレビューに表示しない：

- 現在通常マップの地点マーカーを別レイヤーで重複表示すること
- 人物ピン
- 代理アイコン
- イベント
- 家の外観ボタン
- 配置アイテム
- 出入口

プレビューの地点マーカーはタップして選択できる。タップで人物移動、イベント開始、通常地点編集を起こさない。

地点一覧も用意し、マーカーが重なった場合や支援技術でも選択できるようにする。

## 11. 編集操作

少なくとも次を提供する。

- `地点を追加`
- 地点一覧またはマーカーによる選択
- 選択中地点の名前入力
- 選択中地点のタイプ選択
- 選択中地点の横位置range
- 選択中地点の縦位置range
- 横位置、縦位置の百分率表示
- `この地点を削除`
- `地点設定を保存`
- `キャンセル`

地点追加：

- 8件未満の時だけ実行できる
- 新しい安定IDを生成する
- 初期名、`general`、安全な初期位置を設定する
- 追加地点を選択する
- 保存前は一時ドラフトだけを更新する

地点削除：

- 2件以上ある時だけ実行できる
- 一時ドラフトから選択地点だけを除外する
- 削除後は配列内の近い地点を選択する
- 保存前はIndexedDBと通常マップを変更しない
- キャンセルで保存済み地点へ戻せるため、地点単位の永続削除確認は必須にしない
- `地点設定を保存` が最終的な明示確定操作になる

ドラッグ操作は追加してよいが必須にしない。range入力と地点一覧は必ず残す。

## 12. 保存、キャンセル、名前編集との整合

地点設定は対象下書き一件を一回の明示保存で更新する。

保存時：

- 地点数、ID、名前、タイプ、座標を検証する
- 下書き名、対象枠、status、createdAtを維持する
- locations全体を更新する
- updatedAtを更新する
- `customMapDrafts` の対象レコード一件だけを書き換える
- 保存成功後だけメモリ上の保存済み下書きを更新する

保存失敗時：

- 以前の保存済み下書きを維持する
- 編集中の地点ドラフト、選択地点、入力値を残す
- 再試行またはキャンセルできる
- 短い自然な日本語で知らせる

キャンセル時：

- 地点ドラフトを破棄する
- 保存済み下書きへ戻す
- IndexedDBへ書き込まない

Milestone 8B-4D-1の下書き名編集を行った場合、保存済み `locations` を失わない。地点設定を保存した場合も、下書き名を失わない。

下書き全体を確認付きで削除した場合は、同じレコード内のlocationsも削除される。背景、通常マップ、画像Blobは削除しない。

## 13. 永続化

IndexedDBバージョン8と既存 `customMapDrafts` ストアを維持する。

- DB9へ上げない
- 新しいストアを追加しない
- 一対象枠一レコードを維持する
- 通常オートセーブで下書きを上書きしない
- 地点保存はSaveCoordinatorまたは同等の既存排他基盤を通す
- 通常世界オートセーブ、背景保存、名前保存と競合してもデータを失わない
- 古い非同期結果が、別対象枠や新しい編集状態を上書きしない
- 保存成功後だけUIを保存済み状態へ切り替える
- `mapVisuals`、`assets`、`assetBlobs`、`items`、`characters`、`events`、相談、履歴を変更しない

Repositoryの更新APIは、部分更新時に既存レコード全体を安全に復元し、変更対象以外を維持する。

## 14. 無関係な再描画とフォーカス

パートナー自律行動、保存状態、時刻等の無関係なStore更新が発生しても、次を失わない。

- 編集対象の室内／庭
- 地点ドラフト
- 選択中地点
- 入力中の地点名
- 地点タイプ
- range値
- 入力フォーカスと可能な範囲の選択位置

全面再描画を維持する場合は、安定したfocus keyまたは同等の方法で編集入力へフォーカスを復元する。入力中に文字が欠けたり、キーボードが閉じ続けたりしないようにする。

## 15. 通常マップとの分離

地点編集、保存、再読込を行っても、このMilestoneでは次を一切変更しない。

- `AppState.mapVisuals` の地点配置
- runtimeの `starterMaps`
- 主人公とパートナーの現在地
- 表示中マップ
- 最短経路グラフ
- 自律行動の目的地
- 「知らない芽」の位置と進行
- 出入口と代理表示
- 家の外観位置
- 基本アイテムスロット

下書き地点は設定画面のプレビューだけに描画する。

## 16. 背景との関係

下書きは背景Asset IDまたはBlobを複製保存しない。

- 現在の対象枠背景をプレビューへ利用する
- 背景変更後は地点プレビューも新しい背景へ追従する
- 背景削除後は仮背景へ戻る
- 背景変更で保存済みカスタム地点を変更しない
- 背景Object URLは既存ライフサイクルを利用する
- 地点編集だけを理由にObject URLを重複生成、早期revokeしない

## 17. 全体リセット

既存の全体リセットは下書きレコード自体を削除するため、追加の地点専用リセット処理を別ストアへ作らない。

- 全体リセット後は下書きなしに戻る
- 背景、人物画像、アイテム画像等の既存リセット仕様を維持する
- customMapDraftsが空でもエラーにしない

地点編集画面内に「すべてを現在地点からやり直す」等の追加リセットは、このMilestoneの必須要件にしない。

## 18. UIとアクセシビリティ

- iPhone Safariの縦画面を優先する
- 最小幅320pxで横スクロールを発生させない
- 主要操作、地点マーカー、地点一覧の操作領域を44px以上にする
- 文字入力、select、range周辺の文字を16px以上にする
- 入力へ明示ラベルを付ける
- 選択中地点、地点タイプ、追加上限、削除不可を色だけで示さない
- 地点マーカーと地点一覧の両方で地点名を読めるようにする
- 保存中、保存成功、保存失敗、追加上限、削除不可を `aria-live` または同等の方法で知らせる
- 保存中は二重保存、二重削除、対象切替を防ぐ
- ホバーを必須にしない
- フォーカス表示を消さない
- 3:4プレビューが画面幅を押し広げない

## 19. セキュリティとプライバシー

- 地点名と下書き名を安全なDOM APIで描画する
- 保存値を検証せずCSS座標へ渡さない
- `innerHTML`、`eval`、`Function`、動的importを使用しない
- 外部通信を追加しない
- 地点名、背景、下書き内容を外部へ送信しない
- 相談プロンプトへカスタム地点を追加しない

## 21. テスト

少なくとも次をテストする。

### 21.1 純粋関数

- 7種類の地点タイプIDと表示名、標準タグが固定されている
- 不明地点タイプをgeneralへ戻す
- 現在のlocationTagsから固定優先順で地点タイプを導出する
- 有効な地点1件から8件を復元できる
- 9件目以降を安定順で除外する
- 不正locationIdの地点だけを除外する
- 重複locationIdは最初だけを残す
- 空名、型違い、制御文字、上限超過を地点Nへ戻す
- 前後Unicode空白を除去する
- 座標の片方だけが不正な場合、その成分だけ復旧する
- 有効地点が0件なら現在地点から初期地点を作る
- 既存DB8のlocations欠損下書きを現在地点から初期化する
- 初期地点が保存後は現在地点変更へ追従しない
