# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 2：二人が動く

## 目的

主人公が地点を選んで家と庭を移動できるようにし、同じ移動基盤を使って開発者パネルからコーディも動かせるようにする。

このMilestoneでは「どこにいるか」と「どの経路で移動するか」を完成させる。コーディの自律的な行動選択はまだ実装しない。

## 操作ルール

- マップ上部の「家の中」「庭」タブは、表示するマップを切り替えるだけである。
- タブ切り替えでキャラクターの現在地を変更しない。
- マップ上の地点ボタンをタップすると、その地点を主人公の移動先として扱う。
- 表示中の別マップにある地点も移動先として選べる。
- 別マップへ移動するときは、玄関と家の前のゲートを経由する。
- 家の外観ボタンは「家の中を見る」ための表示切り替えとして残し、キャラクターを瞬間移動させない。
- 移動中に別の地点を押した場合は、新しい移動を重ねず「移動中です」と案内する。

## 実装する

### 1. 地点参照型

マップIDと地点IDの組を共通型として追加する。

```ts
type LocationRef = {
  mapId: MapId;
  locationId: string;
};
```

キャラクターの現在地、経路、移動先で同じ型を使用する。

### 2. 全マップ横断の接続グラフ

`connectedLocationIds`を同一マップ内の辺として扱う。

`gateway`は、現在地点から`destinationMapId`と`destinationLocationId`への辺として扱う。

ノードキーは、マップをまたいでも衝突しない形式にする。

例：

```text
starter_house_interior:entrance
starter_garden:front_of_house
```

無効なマップID、地点ID、接続先を静かに無視して瞬間移動させず、開発時に原因を確認できる形にする。

### 3. 最短経路

幅優先探索などを使い、開始地点から目的地点までの最短経路を求める純粋関数を追加する。

経路には開始地点と目的地点を含める。

例：

```text
テーブル
→ 玄関
→ 家の前
→ 庭
```

経路が存在しない場合は、移動を開始せずUIへ失敗を返す。

### 4. 移動状態

移動中のキャラクターを状態として管理する。

最低限、次を識別できること。

- 移動していない
- 移動中
- 現在の経路
- 次に進む地点
- 最終目的地

`mapId`と`locationId`は、経路の各地点へ到着した時点で更新する。

表示専用座標を現在地の真実として使用しない。

### 5. 主人公の移動

地点ボタンをタップすると主人公の移動を開始する。

- 現在地と同じ地点では移動しない
- 同一マップ内では接続地点を順に通る
- 別マップではゲートを通る
- 接続されていない地点へ直接飛ばない
- 移動中は現在地と目的地を画面内の`aria-live`領域で案内する

### 6. 移動表示

一辺ごとに短い間隔で地点を進め、ピンが地点間を移動していることが分かる軽い演出を付ける。

目安：一辺300〜450ms。

正確な秒数はバランス値であり、定数へまとめる。

`prefers-reduced-motion: reduce`の場合は、長いアニメーションを行わず目的地へ即時反映してよい。

移動タイマーが重複しないようにし、リセット時には進行中の移動も安全に停止する。

### 7. マップ間移動と代理表示

キャラクターがゲートを越えて別マップへ入った時点で、通常ピンと代理表示を現在状態から再計算する。

- 表示中マップへ到着したキャラクターは通常ピンになる
- 表示中マップから出たキャラクターは入口の代理表示になる
- 代理表示は実際の現在地を書き換えない
- マップタブの表示状態と移動状態を混同しない

### 8. コーディの開発者移動

開発者パネルに、主人公とコーディの現在地を表示する。

コーディについて、全マップの地点から目的地を選び、同じ経路探索と移動処理を使って移動させられる開発用操作を追加する。

コーディを通常画面からユーザーが直接移動させる機能は追加しない。

### 9. 現在の様子

固定文ではなく、少なくとも主人公とコーディの現在地を状態から表示する。

例：

```text
主人公は庭へ移動中です。
コーディは作業台にいます。
```

このMilestoneでは行動名や台詞は追加しない。

### 10. テスト

最低限、次を自動テストする。

- 同一マップ内の最短経路
- 室内から庭への経路が玄関と家の前を通る
- 庭から室内への逆方向経路
- 経路の連続する各地点が、通常接続またはゲートで結ばれている
- 存在しない地点への移動を開始しない
- 現在地と同じ地点では移動しない
- 一段進むごとにキャラクターの`mapId`と`locationId`が更新される
- 移動完了後に移動状態が解除される
- リセットで現在地と移動状態が初期化される
- マップを越えたとき代理表示対象が更新される
- 主人公とコーディが同じ移動基盤を利用する

タイマーに依存する部分と経路・状態更新の純粋関数を分離し、純粋関数を中心にテストする。

## 完成条件

- 主人公が地点ボタンから任意の地点へ移動できる
- 室内と庭の間をゲート経由で移動できる
- 経路外の地点へ飛ばない
- 表示マップの切り替えだけでは現在地が変わらない
- コーディを開発者パネルから同じ移動基盤で動かせる
- 通常ピンと代理表示が現在地に応じて切り替わる
- 移動中の案内が読み上げ可能である
- `prefers-reduced-motion`へ対応する
- リセット後に移動タイマーが残らない
- typecheck、test、buildが成功する
- GitHub ActionsのCIが成功する
- IndexedDB、自律行動、イベントなど範囲外の機能を追加していない
