# 次の実装タスク

この文書には、Codexへ渡す依頼文を何度も読み返さずに済むよう、現在実装する一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-4D-1：カスタムマップ下書きの土台

## 目的

MVPの実行マップは、室内 `starter_house_interior` と庭 `starter_garden` の二枠を維持する。

各枠へ一件ずつ、通常マップへまだ反映しないカスタムマップ下書きを作成できるようにする。

このMilestoneでは、下書き名の作成、編集、保存、再読込、確認付き削除と、現在の背景・地点を使う読み取り専用プレビューだけを扱う。

地点の追加、地点タイプ、出入口、代理位置、アイテムスロット、通常マップへの反映は後続Milestoneへ分ける。

## MVP内での位置付け

製品仕様では、カスタムマップの手順を次の順で扱う。

1. 背景画像
2. 地点配置
3. 地点タイプ
4. 出入口接続
5. 代理位置
6. 基本アイテムスロット
7. プレビューと保存

背景画像の登録はMilestone 8B-3Bで既に実装済みである。

そのため8B-4D-1では、新しい背景画像管理を重複して作らず、現在の室内または庭へ登録されている背景画像を下書きプレビューに利用する。背景がない場合は既存の仮背景を利用する。

## このMilestoneで変えないもの

- `MapId` のruntime unionを変更しない
- 実行マップは `starter_house_interior` と `starter_garden` の二件を維持する
- 三枚目以降の実行マップを追加しない
- 表示中マップ、主人公とパートナーの `mapId`、`locationId` を変更しない
- 既存の地点ID、地点名、地点タイプ、位置、接続、出入口を変更しない
- 代理位置、庭の家の外観位置を変更しない
- 基本アイテムスロットの位置、割当を変更しない
- 自律行動、イベント、最短経路、移動速度、移動中状態を変更しない
- 現在の背景画像を複製、移動、所有者変更しない
- `assets`、`assetBlobs`、`mapVisuals` の既存レコード構造を破壊的に変更しない
- 新しい画像アップロード、画像形式、画像上限、Object URL生成経路を追加しない
- 外部通信、外部依存、API接続を追加しない

## 1. 固定対象枠

カスタムマップ下書きの対象は次の二件だけとする。

```ts
type CustomMapTargetId =
  | "starter_house_interior"
  | "starter_garden";
```

意味：

- `starter_house_interior` は室内枠
- `starter_garden` は庭枠
- 一つの対象枠につき保存済み下書きは最大一件
- 下書きは新しいruntime mapIdではない
- 下書き作成だけでは現在のプリセットマップを置き換えない

対象枠からマップ種別を導出する。

- 室内枠：`interior`
- 庭枠：`outdoor`

マップ種別をユーザー入力または保存値から自由に変更しない。

## 2. 安定データ

IndexedDBへ次と同等の意味を持つ安定データを保存する。

```ts
type CustomMapDraft = {
  saveSlotId: "main";
  targetMapId: CustomMapTargetId;
  name: string;
  status: "draft";
  createdAt: string;
  updatedAt: string;
};
```

正確な型名、ファイル名、関数分割は既存構造へ合わせてよい。

保存しないもの：

- 編集中の一時入力
- フォーカス状態
- 削除確認状態
- 開閉中のカードやモーダル状態
- DOM座標、CSS文字列、Object URL
- 背景画像のBlobまたは複製参照
- 地点、出入口、代理位置、アイテムスロットの編集値
- 通常マップへ反映済みかを示す状態

この段階の `status` は `draft` だけとする。`ready`、`active`、`published` 等を追加しない。

## 3. IndexedDBバージョン8

IndexedDBバージョンを7から8へ上げる。

新しいストア：

```text
customMapDrafts
```

キー：

```ts
[saveSlotId, targetMapId]
```

要件：

- DB7からDB8への更新で既存ストアと既存レコードを削除しない
- `mapVisuals`、`assets`、`assetBlobs`、`items`、`characters`、`events`、相談、履歴を維持する
- `appMeta` のschemaVersionを8へ更新する
- 起動時に室内と庭の下書きを読み込めるようにする
- 下書きが一件壊れていても、もう一件と通常セーブを捨てない
- 下書き保存は `customMapDrafts` 一件だけを更新し、`mapVisuals` を同時更新しない
- 下書き削除は対象レコードだけを削除し、画像アセットを削除しない

既存の通常オートセーブで下書きを毎回上書きしない。下書きは明示的な作成・更新・削除操作で保存する。

## 4. 検証と部分復旧

保存値を直接UIへ渡さず、純粋な検証関数を通す。

### 4.1 targetMapId

- `starter_house_interior` または `starter_garden` だけを受理する
- 不明値、空文字、型違いはレコード全体を不採用とする
- レコード内のtargetMapIdとIndexedDBキーが一致しない場合は不採用とする

### 4.2 name

- 文字列だけを受理する
- 前後のUnicode空白を除去する
- 1文字以上40文字以下とする
- 制御文字を受理しない
- 空、型違い、制御文字、上限超過の場合は対象枠ごとの固定初期名へ戻す

固定初期名：

- 室内：`カスタム室内`
- 庭：`カスタム庭`

文字数の数え方は、既存の入力検証に合わせた安全な方式を用いる。表示崩れを起こすほど過大な名前を保存しない。

### 4.3 status

- 保存値にかかわらず、この段階では `draft` へ正規化する

### 4.4 createdAt / updatedAt

- Date.parse可能な文字列だけを受理する
- 新規作成時は同じ現在時刻を設定する
- 更新時はcreatedAtを維持し、updatedAtだけを更新する
- 読込時に不正な場合は項目単位で安全な固定値へ戻す
- 日時の破損だけで下書き名を失わない

### 4.5 一件制約

ストアキーにより、一対象枠一件を保証する。

同じ対象枠へ新規作成操作を行った場合、既存下書きを無断で上書きしない。UIでは既存下書きの編集へ案内する。

## 5. 下書き作成

設定画面のマップ設定付近へ、`カスタムマップ下書き` または同等の区画を追加する。

室内と庭を別カードまたは明確な区画で表示する。

下書きがない場合：

- `室内の下書きを作る`
- `庭の下書きを作る`

または同等の対象が明確な操作を表示する。

作成開始時：

- 固定初期名を一時ドラフトへ入れる
- 対象枠とマップ種別を表示する
- 現在の背景または仮背景と現在の地点をプレビューする
- まだIndexedDBへ保存しない
- 通常マップ、人物、イベント、自律行動を変更しない

作成保存時：

- 名前を検証する
- `createdAt` と `updatedAt` を設定する
- 対象枠の一件を `customMapDrafts` へ保存する
- 保存成功後だけ保存済みカードへ切り替える

キャンセル時：

- 未保存の一時ドラフトを破棄する
- 通常マップと保存済み下書きを変更しない

## 6. 下書き名の編集

保存済み下書きに `名前を編集` または同等の操作を用意する。

編集開始時：

- 保存済み名を一時ドラフトへコピーする
- 保存済みレコードを直ちに変更しない

保存時：

- 名前を検証する
- `createdAt` を維持する
- `updatedAt` を更新する
- 保存成功後だけ表示名へ反映する

保存失敗時：

- 以前の保存済み下書きを維持する
- 入力中の名前を残す
- 再試行またはキャンセルできる
- エラーを短い自然な日本語で知らせる

キャンセル時：

- 保存済み名へ戻す
- IndexedDBへ書き込まない

自律行動等による無関係な再描画で、編集中の名前、対象枠、フォーカスを失わない。

## 7. 確認付き削除

保存済み下書きに削除操作を用意する。

一回目の操作では確認状態へ入り、二回目の明示操作で削除する。

削除対象：

- `customMapDrafts` の該当対象枠レコードだけ

削除しないもの：

- 現在の室内または庭マップ
- 背景画像と画像Blob
- 地点配置
- 出入口、代理位置、家の外観位置
- アイテムスロット
- 人物、イベント、アイテム、相談、履歴

削除成功後は、対象枠を「下書きなし」表示へ戻す。

削除失敗時は下書きを表示したままにし、再試行できる。

## 8. 読み取り専用プレビュー

作成中、編集中、保存済み表示のいずれでも、対象枠の3:4プレビューを表示する。

プレビューの正は現在の通常マップ状態とする。

表示する：

- 現在登録されている背景画像
- 背景がない、または読込失敗時の既存仮背景
- Milestone 8B-4Aで保存された現在の地点配置
- 地点名
- 対象枠が室内か庭か
- 下書き名
- `下書き` であり通常マップへ未反映であること

表示しない、または操作させない：

- 人物ピン
- 代理アイコン
- イベント
- 家の外観ボタン
- 配置アイテム
- 地点移動操作
- 地点編集操作
- 背景変更操作

地点マーカーは読み取り専用とし、タップで人物移動や地点編集を起こさない。

背景画像の変更・削除は既存のマップ背景設定から行う。このMilestoneでは下書き内に背景Asset IDを保存しない。

そのため：

- 背景を変更すると下書きプレビューも現在の背景へ追従する
- 背景を削除すると下書きプレビューは仮背景へ戻る
- 背景が変わっても下書き名と下書きレコードは残る
- 背景Blobを下書き用に複製しない
- 新しいObject URL管理経路を増やさず、既存の安定した背景URLを利用する

## 9. 全体リセット

既存の全体リセットへ、室内と庭の `customMapDrafts` レコード削除を追加する。

- 下書きだけを残さない
- DB8ストアが空でもエラーにしない
- リセット後は設定画面を「下書きなし」へ戻す
- 既存リセットの背景、人物画像、地点、出入口、アイテムスロット等の挙動を変更しない

## 10. UIとアクセシビリティ

- iPhone縦画面を優先する
- 最小幅320pxで横スクロールを発生させない
- 主要操作領域を44px以上にする
- 文字入力を16px以上にする
- 名前入力へ明示ラベルを付ける
- 室内と庭、保存済みと編集中、下書きなしと下書きありを色だけで区別しない
- 保存中、保存成功、保存失敗、削除確認、削除結果を `aria-live` または同等の方法で知らせる
- 保存中は同じ対象への二重保存、二重削除を防ぐ
- 背景プレビューの画像は装飾扱いとし、下書き名と対象枠を文字で読めるようにする
- ホバーを必須にしない

モーダルを使うか、設定画面内で展開するかは既存UIに合わせてよい。画面全体を不必要に拡大させる入力サイズや、iPhoneで操作不能になる横並びを追加しない。

## 11. 保存と非同期競合

- 下書き作成、更新、削除はSaveCoordinatorまたは同等の既存排他基盤を通す
- 同じ対象枠への保存操作を直列化する
- 古い非同期結果が、新しい編集状態や別対象枠を上書きしない
- 画面移動やキャンセル後に遅れて完了した結果を安全に扱う
- 保存成功後だけ保存済みUIへ切り替える
- 保存失敗時は旧安定データを維持する
- 通常の世界オートセーブと競合しても、下書きレコードまたは通常セーブを失わない

背景画像のObject URLは既存ライフサイクルを利用し、このMilestoneの下書き操作だけを理由に再取得、重複生成、早期revokeしない。
