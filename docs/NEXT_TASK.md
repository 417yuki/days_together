# 次の実装タスク

この文書は、Codexへ長い依頼文を毎回貼らずに済むよう、次の一件だけを記載する。

作業開始前に `AGENTS.md`、`docs/INDEX.md`、`docs/PRODUCT_SPEC.md`、`docs/ITEM_VISUALS.md`、`docs/ROADMAP.md` を読むこと。

## 対象

Milestone 8B-3B：室内・庭の背景画像

## 目的

既存の二つのプリセットマップへ、端末内のPNG、JPEG、WebP画像を一枚ずつ任意登録できるようにする。

対象は次だけとする。

- 室内 `starter_house_interior`
- 庭 `starter_garden`

登録画像はマップの最背面へ表示し、その上へ既存の地点ボタン、人物ピン、別マップ代理表示、家の外観、イベントマーカーを重ねる。

画像は任意である。画像がない、削除した、壊れている、参照が不正、読込に失敗した場合も、現在のCSSによる仮背景を表示し、移動、自律行動、イベント、アイテム、相談を継続する。

## このMilestoneで変えないもの

- マップID、マップ種別、地点IDを変更しない
- 地点座標、経路、ゲート、代理位置を変更しない
- キャラクターピン画像、人物名、現在地を変更しない
- ピンの接地点、表示倍率、切抜き位置を編集するUIを追加しない
- 背景上で地点を置き直す機能を追加しない
- ユーザー作成マップを追加しない
- アイテム配置、アイテムスロットを追加しない
- 画像の圧縮、回転、実Blobの切抜き、色補正を行わない
- 外部通信、画像生成API、クラウド保存を追加しない
- アイテム画像、人物画像、カテゴリ共通画像の既存挙動を変更しない

接地点、表示倍率、切抜き位置の調整はMilestone 8B-3Cへ分ける。地点マッピングとカスタムマップはMilestone 8B-4へ分ける。

## 1. 背景参照データ

背景の安定参照を、マップ定義そのものとは分けて保存する。

少なくとも次の意味を持つ型を用意する。

```ts
type MapVisualState = {
  saveSlotId: "main";
  mapId: "starter_house_interior" | "starter_garden";
  backgroundAssetId: string | null;
  updatedAt: string;
};
```

正確な型名とファイル分割は既存構造へ合わせてよい。

ルール：

- 一つの対象マップにつき現在背景は最大一枚
- 初期値は `backgroundAssetId: null`
- 既存セーブにレコードがない場合は `null`
- 空文字、制御文字、過度に長い参照は `null` 相当として部分復旧する
- 不正な背景参照だけでマップ、地点、人物、イベントを捨てない
- Object URL、Data URL、ファイル名を安定参照として保存しない

## 2. アセット種類

既存のアセット基盤へ背景画像を追加する。

```ts
type AssetKind = "item_image" | "character_pin" | "map_background";
```

背景画像では次を固定する。

- `kind` は `"map_background"`
- `ownerId` は `"starter_house_interior"` または `"starter_garden"`
- 新しい画像へ変更する場合は新しい `assetId` を発行する
- アイテム画像と人物画像のkind、owner検証を緩めない
- ownerIdと対象mapIdが一致しない画像を表示しない

## 3. 受け付ける画像

対応形式と基本検証は既存画像機能と同じとする。

- PNG `image/png`
- JPEG `image/jpeg`
- WebP `image/webp`
- 最大10 MiB
- 0 byte拒否
- MIME typeと先頭バイトの一致を検証
- SVG、GIF、HEIC、HEIF、不明形式を拒否
- originalNameの制御文字と長さを検証

```html
<input type="file" accept="image/png,image/jpeg,image/webp">
```

画像選択直後には保存しない。

## 4. 設定画面

既存「設定」画面へ、「マップ背景」または同等のセクションを追加する。

### 4.1 室内背景

- 見出し「室内」
- 現在背景のプレビュー、または「仮背景を使用中」
- `画像を追加` または `画像を変更`
- 背景がある場合 `画像を削除`

### 4.2 庭背景

- 見出し「庭」
- 現在背景のプレビュー、または「仮背景を使用中」
- `画像を追加` または `画像を変更`
- 背景がある場合 `画像を削除`

### 4.3 選択後

保存前に次を表示する。

- 現在の3:4マップ枠へ `object-fit: cover` で収めたプレビュー
- ファイル名
- 形式
- 容量
- `この背景を保存`
- `選び直す`
- `キャンセル`

室内と庭の操作状態は独立させる。片方の選択、保存、削除がもう片方のプレビューやObject URLへ触れないようにする。

保存中、削除中は対象背景の二重操作を無効化する。

### 4.4 削除確認

`画像を削除` を押しただけでは削除しない。

確認時に次を明記する。

- 背景画像だけを削除する
- マップ、地点、人物、アイテム、イベント、セーブデータは残る
- 削除後は現在の仮背景へ戻る

明示的な `背景画像だけを削除する` 操作後に実行する。

## 5. IndexedDB

データベースバージョンを6から7へ上げる。

既存ストアを変更、削除しない。

次を追加する。

- `mapVisuals`

推奨キー：

```ts
mapVisuals: [saveSlotId, mapId]
```

バージョン6の既存セーブを壊さず7へ移行する。

- 既存の人物画像、アイテム画像を維持する
- マップ、人物位置、イベント、相談、パートナー設定、台詞、履歴、アイテムを維持する
- `mapVisuals` が空でも正常起動する
- 室内または庭の一件が壊れていても、もう一件とゲーム本体を復元する

## 6. 原子的保存

背景操作専用のRepository APIまたは既存構造へ沿う同等処理を用意する。

### 6.1 追加

一つのIndexedDB transaction内で次を完了する。

1. 対象mapIdが二つのプリセットマップのどちらか確認
2. `assets` へ `map_background` メタデータを保存
3. `assetBlobs` へBlobを保存
4. `mapVisuals.backgroundAssetId` を新しいassetIdへ更新

全処理成功後だけメモリ状態へ反映する。

### 6.2 変更

一つのtransaction内で次を完了する。

1. 新しいメタデータとBlobを保存
2. mapVisuals参照を新assetIdへ更新
3. 旧 `map_background` メタデータとBlobを削除

途中失敗時は旧背景と旧参照を維持する。

### 6.3 削除

一つのtransaction内で次を完了する。

1. `backgroundAssetId` を `null` へ更新
2. 対応する `map_background` メタデータを削除
3. 対応するBlobを削除

画像が既に欠損していても参照を安全に `null` へ戻せるようにする。

### 6.4 保存失敗

- 現在の背景参照を変更しない
- 旧背景を消さない
- 選択中の新画像とプレビューを残す
- 再試行またはキャンセルできる
- 読み上げ可能な日本語エラーを表示する
- ゲーム本体と自律生活を続行する

通常のSaveSnapshotへBlob、Object URL、プレビュー状態を含めない。

## 7. マップ描画

背景画像は `map-canvas` 内の最背面レイヤーとして表示する。

レイヤー順は次を守る。

1. 背景画像または既存仮背景
2. 家の外観等のマップ装飾
3. 地点ボタン
4. イベントマーカー
5. 人物ピン、代理表示

正確なz-index値は既存CSSへ合わせる。

背景画像の表示：

- `position: absolute`
- `inset: 0`
- `width: 100%`
- `height: 100%`
- `object-fit: cover`
- `object-position: center`
- 装飾画像として `alt=""` または `aria-hidden="true"`
- ポインター操作を受け取らない
- 320px幅で横スクロールを発生させない

背景画像が読込中、欠損、破損、owner不一致、kind不一致の場合は、既存仮背景を見せたままにする。壊れた画像アイコンや空白を表示しない。

背景を変更しても既存地点座標を自動調整しない。今回のプレビューと実表示は現在の3:4マップ枠で同じ `object-fit: cover` を使用する。

## 8. 画像取得とキャッシュ

背景画像はマップ表示で継続利用するため、無関係な再描画ごとにIndexedDBを読み直したりObject URLを再生成したりしない。

マップごと、またはassetIdごとの小さなキャッシュと世代照合を用意する。

- 同じassetIdは既存Object URLを再利用する
- パートナーの移動、台詞、イベント状態更新だけではBlob取得を再開始しない
- backgroundAssetIdが変わった時だけ新しい画像を取得する
- 画像変更、削除、リセット、アプリ破棄時に不要URLをrevokeする
- 古い取得、検証、保存結果を現在の別マップ背景へ表示しない
- `pagehide` でURLを安全に解放する
- bfcacheからの `pageshow.persisted` では安定参照から必要背景を再取得する
- 読込失敗を無限再試行しない

## 9. リセット

全体リセットでは次を行う。

- 室内と庭のbackgroundAssetIdを `null` へ戻す
- 対応する `map_background` メタデータとBlobを削除する
- 背景Object URLをrevokeする
- 現在の仮背景へ戻す
- 人物画像、アイテム画像については既存リセット仕様を維持する

## 10. アクセシビリティとモバイル

- ファイル入力文字は16px以上
- 操作領域は44px以上
- ホバー必須にしない
- 保存、削除、読込失敗を `aria-live` で通知する
- 背景画像だけにマップの意味を依存しない
- 地点名、人物名、イベント名は既存テキストとaria-labelで維持する
- 色だけで状態を区別しない
- `prefers-reduced-motion` を損なう背景アニメーションを追加しない

## 11. セキュリティとプライバシー

- 外部通信を追加しない
- 外部画像URLを保存、読込しない
- 背景画像をパートナーチャットや相談プロンプトへ含めない
- ファイルの絶対パスを取得、表示、保存しない
- ファイル名をHTMLとして解釈しない
- `innerHTML`、`eval`、`Function`、動的importを使用しない
- Blob URLはUI表示以外へ使用しない

## 13. テスト

少なくとも次を自動テストする。

### 13.1 検証

- `map_background` の正しいownerIdを受理する
- 不明mapId、owner不一致、kind不一致を拒否する
- PNG、JPEG、WebPの既存検証を維持する
- 不正なbackgroundAssetIdだけをnullへ部分復旧する

### 13.2 保存

- DB6から7へ移行し既存ストアとデータを維持する
- `mapVisuals` を追加する
- 新規背景のメタデータ、Blob、参照を原子的に保存する
- 置換成功時だけ旧背景を削除する
- 置換失敗時は旧背景を維持する
- 削除成功時だけ参照、メタデータ、Blobを消す
- 室内の失敗が庭背景を壊さない
- SaveSnapshotへBlob、Object URL、プレビューを含めない

### 13.3 表示とライフサイクル

- 画像なしでは既存仮背景を表示する
- 有効な背景だけを対象マップへ表示する
- 読込失敗時は仮背景へ戻る
- 背景の上に地点、イベント、人物、代理表示を維持する
- 同じassetIdで不要にBlob取得とObject URL生成を繰り返さない
- 古い非同期結果を別マップへ表示しない
- pagehideでURLを解放し、bfcache復元時に再取得できる

既存の移動、イベント、相談、パートナー設定、アイテム、個別画像、キャラクターピン画像、保存復元テストを維持する。

## 手動確認

1. 既存セーブで起動する。
2. 「設定」を開く。
3. 室内背景を選び、プレビュー後に保存する。
4. 庭背景へ別画像を保存する。
5. 室内を開き、室内画像の上で地点と人物ピンを操作できることを確認する。
6. 庭を開き、庭画像の上で家の外観、地点、花、人物ピンを操作できることを確認する。
7. パートナーを別マップへ移動し、代理表示が背景の上へ出ることを確認する。
8. ページを再読込し、二枚の背景が残ることを確認する。
9. 室内背景を変更し、庭背景が変わらないことを確認する。
10. 室内背景だけを削除し、室内は仮背景へ戻り、庭背景は残ることを確認する。
11. 戻る、進む等でbfcache復元し、背景が壊れず再表示されることを確認する。
12. パートナーの表示名、設定revision、人物画像、現在地、イベント、花の相談結果、アイテム画像が残ることを確認する。
