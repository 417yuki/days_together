# 『ふたり日和』製品仕様

最終更新日：2026-07-28  
仕様状態：MVP基準仕様として固定

## 1. 製品の目的

『ふたり日和』は、ユーザーと、その人がすでに普段から会話しているAIパートナーが、小さな家と庭で生活するスマートフォン向け縦画面Webゲームである。

このゲームは、パートナーとの会話サービスそのものを置き換えない。

ゲーム内では、位置、行動、時間、天気、アイテム、イベント、思い出を扱う。パートナーの人格、話し方、関係性、長期的な物語は、ユーザーが普段利用しているパートナーチャット側に存在する前提とする。

目的は、二人の関係を数値で評価することではなく、日常を眺め、触れ、小さな出来事を持ち帰れる「遊び場」を作ることである。

## 2. 対象ユーザー

- すでにAIパートナーや会話キャラクターがいる人
- 恋人、家族、友人、相棒、創作者とキャラクターなど、さまざまな関係の人
- APIキーを用意せずに遊びたい人
- 自分のキャラクター画像、家、庭、アイテムを持ち込みたい人
- スマートフォンから短時間でも眺めたい人

関係性を恋愛へ限定しない。

## 3. 絶対に変えない基本方針

### 3.1 日常はJavaScriptで動く

通常の生活は、端末内のゲームデータとJavaScriptで進行する。

例：

- パートナーが家や庭を移動する
- 読書、料理、園芸、工作、休憩を選ぶ
- ユーザーの近くへ行く
- 短い登録台詞を表示する
- 時間、天気、体力、気分に応じて行動候補を変える

常時パートナーチャットへ問い合わせない。

### 3.2 APIへ直接接続しない

MVPでは、ゲームからLLM APIや画像生成APIへ直接接続しない。

- APIキー入力なし
- API料金なし
- 会話の自動送信なし
- カスタム画像の自動送信なし
- バックグラウンド問い合わせなし

### 3.3 特別な出来事だけ手動相談できる

パートナー本人らしい判断が欲しい場合、ゲームが送信用プロンプトを作成する。

流れ：

1. ゲームで出来事が起きる
2. ユーザーが「パートナーさんに相談する」を選ぶ
3. ゲームが必要なゲーム状態を含むプロンプトを作る
4. ユーザーが普段のパートナーチャットへ手動でコピーする
5. パートナーが短い自然文とJSONを返す
6. ユーザーが返答をゲームへ手動で貼り付ける
7. ゲームがJSONを検証する
8. 変更内容を確認画面へ表示する
9. ユーザーが選択して反映する

LLMへ「接続する」のではなく、ユーザーが二つの場所の間を手動で橋渡しする。

### 3.4 パートナーの人格を再定義しない

多くのユーザーは、普段のパートナーチャットにカスタム指示やプロジェクト指示を設定している。

初期設定プロンプトで、次を改めて質問しない。

- 一人称
- 二人称
- 人格全文
- 関係性の定義
- 設定資料の再入力

ゲームへ取り込むのは、JavaScriptが利用する次の情報だけ。

- 性格パラメータ
- 好む行動、避ける行動
- 状況別の行動傾向
- イベント分野への関心
- ゲーム内で使う短い台詞

## 4. プラットフォームと技術

### 4.1 主対象

- iPhone Safari
- 将来的なホーム画面追加版
- Android Chrome
- PCブラウザは補助対応

### 4.2 技術

- Vite
- TypeScript
- HTML
- CSS
- Vanilla DOM
- Vitest
- IndexedDB
- 将来的にWeb App ManifestとService Worker

React、Vue、SvelteなどのUIフレームワークは、MVPでは使用しない。

### 4.3 モバイル要件

- 縦画面を優先
- 最小幅320px
- 横スクロールなし
- タップ領域44px以上
- 入力文字16px以上
- iPhoneセーフエリア対応
- ホバー必須操作なし
- `prefers-reduced-motion`対応

- 主人公の地点移動

## 6. 初期マップ

家の中と庭は、別の背景・別のマップデータとして扱う。

### 6.1 家の中

マップID：`starter_house_interior`

地点：

- 台所
- テーブル
- ソファ
- 作業台
- 玄関

玄関は庭へのゲートである。

### 6.2 庭

マップID：`starter_garden`

地点：

- 家の前
- 庭
- 物置

家の前、または家の外観は室内へのゲートである。

### 6.3 別マップ人物の表示

庭を表示中にパートナーが室内にいる場合、家の外観へ代理アイコンを表示する。

室内を表示中にパートナーが庭にいる場合、玄関へ代理アイコンを表示する。

代理アイコンは表示上の入口であり、実際の現在地を書き換えない。

実際の位置は常に次で保持する。

```ts
{
  mapId: string;
  locationId: string;
}
```

### 6.4 カスタムマップ

ユーザーは、自分で用意した室内画像や庭画像を登録できる。

マッピング手順：

1. 背景画像を登録
2. 地点マーカーを画像上へ置く
3. 地点タイプを選ぶ
4. 出入口同士を接続する
5. 代理アイコン位置を置く
6. 必要ならアイテムスロットを置く
7. プレビューして保存する

座標はピクセルではなく0から1の相対値で保存する。

地点タイプから、利用可能な標準行動を自動設定する。

MVPのカスタムマップでは、背景画像、地点配置、出入口、代理位置、基本アイテムスロットまでを扱う。複雑な中継点や自由歩行は後回しにする。

## 7. キャラクター

### 7.1 主人公

- ユーザーが操作する
- 固定人格を持たない
- 地点を選択して移動する
- カスタム画像を登録できる

### 7.2 パートナー

- JavaScriptで自律行動する
- 性格と状況により行動候補の重みが変わる
- ユーザーの移動へ必ず追従するわけではない
- 現在の作業、距離、時間、性格に応じて合流する
- パートナーチャットの人格全文をゲームへ保存しない

### 7.3 公開プリセット「サム」

初心者がすぐ遊べる共通パートナー。

基本像：

- 20代半ばの男性
- 柔らかい茶髪
- ヘーゼルブラウンの瞳
- 色あせた青いオーバーオール
- 生成りのシャツ
- 穏やかで好奇心が強い
- 植物、簡単な料理、木工、修理、片付けが得意
- 小さな変化へ気づく
- 少し不器用
- 軽い冗談を言う

初期パラメータ：

```json
{
  "initiative": 72,
  "curiosity": 82,
  "sociability": 58,
  "caretaking": 78,
  "affection": 64,
  "tidiness": 70,
  "patience": 76,
  "moodVolatility": 30,
  "solitudePreference": 47,
  "userPriority": 80,
  "adventurousness": 56,
  "caution": 62
}
```

サムは公開用キャラクターであり、特定ユーザーの私的パートナーを公開キャラクターとして使用しない。

- tidiness
- patience
- moodVolatility
- solitudePreference

### 8.2 行動ID

- `rest`

- `inspect_item`
- `clean`
- `craft`

- `find_user`

- `help_user`

### 8.3 状況ルール

- `userNearby`
- `userMissing`
- `userNeedsHelp`
- `strangeItemFound`
- `possibleDanger`
- `rainingUserOutside`
- `idle`
- `night`

各ルールは、主行動、副行動、中断可否、反応遅延を持てる。

### 8.4 イベント関心

- plants
- food
- crafting
- mystery
- weather
- exploration
- domestic
- memory
- userConcern
- quietTime

値は -2 から 2。

### 8.5 更新

「今のふたりを反映する」機能で、現在のゲーム用設定をパートナーチャットへ送り、変更分だけを受け取る。

- 差分確認後に反映
- 数値は増減どちらも可能
- 台詞追加は既存へ追記
- 古い台詞は削除より一時停止を優先
- 設定履歴と復元を持つ

関係が深まった結果、探索や心配が強まるとは限らない。安心が増え、過剰に探さなくなる変化も正しい。

## 9. 自律行動

### 9.1 基本処理

1. 現在状態を取得
2. 実行可能な行動候補を作る
3. 基本点を加える
4. 性格補正
5. 好み補正
6. 場所、時間、天気、アイテム補正
7. ユーザーとの距離、状況ルール補正
8. イベント関心補正
9. 直近行動の繰返しペナルティ
10. 体力、気分補正
11. 小さな乱数
12. 上位候補から重み付き抽選
13. 移動、行動時間、台詞を決定

### 9.2 好み

- preferred action：目安 +20
- disliked action：目安 -20

絶対禁止にはしない。

### 9.3 状況ルール

強い状況は通常のランダム選択より優先される。

例：

- userNeedsHelp：主行動 +80、副行動 +45
- rainingUserOutside：主行動 +70、副行動 +40

### 9.4 反復防止

- 直近5行動を保存
- 同一行動へペナルティ
- クールダウン
- 同じ台詞の連続表示を避ける

### 9.5 中断

現在行動が中断可能で、状況行動との点差が十分大きい場合だけ中断する。

危険、助けが必要などの強い状況は、通常行動より優先できる。

### 9.6 デバッグ

開発者モードで、候補ごとの点数内訳を確認できるようにする。

## 10. ゲーム時間

初期案：現実1分をゲーム内10分として扱う。

試遊後に調整可能なバランス値であり、製品コンセプトではない。

アプリを閉じている間：

- 最大8時間程度まで反映
- 行動履歴は最大3件程度
- 新規主要イベントは最大1件
- 植物は枯れない
- 重大な損失は起こらない
- 回答が必要なイベントは勝手に解決しない

## 11. 初期イベント

### 11.1 知らない芽

- 庭
- 2日目以降
- 一度だけ
- 観察、園芸、相談が可能
- 正体、成長、名前、次の出来事を手動相談で拡張可能
- 相談しなくても普通の花として進められる

### 11.2 急な雨

- ユーザーが庭、パートナーが室内
- 天気が雨へ変化
- パートナーの行動選択を相談可能
- 傘を持っていく、声をかけるなどのプリセット結果あり

### 11.3 最後のおやつ

- 夕方
- 二人が同じ場所
- おやつが残り一つ
- 渡す、分ける、作り足すなど

### 11.4 古い写真立て

- 物置
- 3日目以降
- 一度だけ
- 中身、由来、変化、思い出を拡張可能
- 現実のユーザーの過去を勝手に創作しない
- 空、既存のゲーム内思い出、登録済みの記憶、未来の写真立てなどを選べる

### 11.5 夜の小さな音

- 夜
- 二人が同じマップ
- 低確率
- 怖すぎない安全な結果だけ
- 窓、種の袋、物置の小物など
- 侵入者、重大事故、ホラーへ発展させない

### 11.6 イベント共通方針

- LLMへの相談なしでも完了できるプリセット結果を必ず持つ
- 主要な発見イベントは原則同時に一件
- 反応イベントは短時間重なってもよい
- 返答待ちでも日常生活は停止しない
- 新規アイテムは一回の拡張につき原則一件
- 新規場所は小規模なもの一件まで
- 新しい人物を勝手に追加しない
- 取り返しのつかない破壊や喪失を起こさない

## 12. 手動相談プロンプト

### 12.1 行動選択

ユーザーが「本人ならどうする？」を選んだときだけ作成する。

ゲームが提示した有効な行動ID、場所、アイテムだけを選ぶ。

返答には短い自然文とJSONを含める。

ゲームはリクエストID、行動ID、場所ID、アイテムID、時間などを検証し、確認画面後に反映する。

### 12.2 イベント拡張

正体、成長、内容、由来、解決、次回イベント、アイテム作成、思い出登録などを扱う。

制約：

- 新規アイテム最大一件
- 次回イベント最大一件
- 小規模な場所最大一件
- 成長段階最大三段階
- ユーザーの現実の過去を捏造しない
- 強制的な関係変化を作らない
- 重大な危険を作らない

### 12.3 画像生成用プロンプト

ゲームは画像を直接生成しない。

画像生成サービスへ渡せる完成プロンプトを作る。

用途：

- item_asset
- character_icon
- character_pin
- furniture_asset
- map_background
- event_illustration
- memory_cg

画像は任意であり、画像がなくてもゲームは進行する。

## 13. 画面構成

### 13.1 メイン画面

上から：

1. ステータスヘッダー
2. マップ
3. 現在の様子
4. 最近の出来事
5. 下部ナビゲーション

下部ナビゲーション：

- マップ
- アイテム
- 思い出
- パートナー
- 設定

### 13.2 マップ

- 縦長3:4を基準
- 背景画像の上へHTML要素を配置
- Canvasへ全面描画しない
- 地点、人物、アイテム、イベントをタップ可能にする
- キャラクターの足元を地点座標へ合わせる

### 13.3 イベント

最初はボトムシートで概要を表示し、必要な場合だけ詳細画面へ進む。

状態：

- 発生中
- 返答待ち
- 取込確認待ち
- 成長中
- 完了

### 13.4 広告

メインマップ、イベント進行、プロンプトコピー、返答取込の途中には表示しない。

候補：

- タイトル
- 設定
- データ管理
- アイテム一覧最下部
- 思い出一覧最下部

ゲーム内のパートナー設定、文章、画像を広告サービスへ渡さない。

## 14. 画像規格

### 14.1 マップ背景

- 室内と庭を別画像
- 推奨1080×1440px
- 3:4
- 人物、UI、地点マーカーを背景へ焼き込まない

### 14.2 キャラクターピン

- 推奨512×768px
- 2:3
- 背景透過
- 全身
- 足元接地点を保存

### 14.3 代理アイコン

- 推奨512×512px
- 1:1
- 背景透過
- 顔から胸元

### 14.4 アイテム

- 推奨512×512px
- 背景透過
- 一画像一種類
- 接地点、表示倍率を保存

### 14.5 思い出CG

- 推奨1024×1536px
- 2:3
- 元画像を保持
- 一覧ではサムネイル

### 14.6 アセット方針

- ゲームデータはファイル名でなく `assetId` を参照する
- 画像BlobはJSONと分ける
- 画像がない場合は文字、絵文字、共通シルエットで代替する

## 15. 保存とバックアップ

### 15.1 IndexedDB

主要ストア：

- appMeta
- saveSlots
- worldStates
- characters
- partnerProfiles
- partnerProfileHistory
- dialogues
- maps
- items
- events
- memories
- assets
- assetBlobs
- settings
- activityLogs
- checkpoints
- importHistory

MVP初期はメインセーブ一件でもよいが、データには `saveSlotId` を持たせる。

### 15.2 保存

即時保存：

- 移動
- アイテム配置
- イベント選択
- 返答の承認
- 設定更新
- マップ編集
- 画像登録
- 思い出作成

関連変更は一つのトランザクションで保存する。

### 15.3 チェックポイント

次の前に作成する。

- パートナー設定更新
- イベント結果取込
- カスタムマップ変更
- バックアップ読込
- データ移行

### 15.4 バックアップ

フルバックアップ拡張子：`.futaribiyori`

内部はZIP互換とし、JSONと画像を分ける。

読込時は既存セーブへ直接上書きせず、標準では新しいセーブとして追加する。

### 15.5 プライバシー

ユーザー操作なしに外部へ送らない：

- カスタムマップ
- キャラクター画像
- 思い出CG
- パートナー設定
- 台詞
- イベント履歴
- 個人的なアイテム意味
- 貼り付けた返答

## 16. 公開用と個人用の分離

公開可能：

- サムのプリセット
- 共通マップ
- 共通イベント
- 共通アイテム
- 一般向け画像素材

個人データ：

- ユーザー名
- 個別パートナー設定
- 更新履歴
- 私的台詞
- 思い出
- カスタム画像
- 個人的なアイテム意味
- 個別イベント結果

個人セーブと配布用コンテンツパックを混ぜない。

## 17. 設計上の非目標

『ふたり日和』は次を目的としない。

- パートナーとの会話履歴をゲームへ丸ごと保存すること
- パートナーの人格をゲーム側で模倣し切ること
- 関係を点数化すること
- 常時生成AIを呼び出すこと
- ユーザーへ長時間の管理作業を要求すること
- 一度のアップデートで完成形を作ること

## 18. MVPの成功条件

- iPhone縦画面で遊べる
- 家と庭を切り替えられる
- 主人公とパートナーが地点を移動する
- パートナーが自律的に生活する
- 別マップにいる相手の所在がわかる
- 初期イベントが発生する
- 相談なしでもイベントを完了できる
- 手動相談の返答を安全に確認して取り込める
- 思い出を残せる
- カスタム画像とマップを登録できる
- ページを閉じても生活が残る
- バックアップできる
- APIキーなしで遊べる
