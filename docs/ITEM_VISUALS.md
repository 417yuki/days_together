# アイテム表示・汎用ビジュアル仕様

最終更新日：2026-07-28  
仕様状態：MVP基準仕様として固定

## 1. 目的

ユーザーがアイテムを一つ登録するたびに、専用の透過画像を用意しなくても遊べるようにする。

画像制作は表現を豊かにする任意機能であり、アイテム登録の入場券にはしない。

## 2. 基本方針

アイテムは、最低限次の情報だけで登録できる。

- 名前
- カテゴリ
- 汎用アイコン
- 説明、タグ、利用可能な操作

個別画像は任意。

## 3. 表示レイヤー

### 3.1 アイテム一覧

アイテム一覧、選択ダイアログ、所持品ピッカーでは、原則として汎用アイコンを使う。

理由：

- 小さい画面で形を揃えやすい
- 個別画像の縦横比に左右されない
- 一覧の読込みが軽い
- 画像を持たないアイテムと混在しても不自然にならない
- ユーザーの素材準備を減らせる

一覧には次を表示する。

- 汎用アイコン
- アイテム名
- 必要に応じて個数、場所、状態

### 3.2 アイテム詳細

詳細画面の大きなビジュアルは、次の優先順位で表示する。

1. 個別画像 `imageAssetId`
2. カテゴリ共通画像 `genericVisualKey`
3. 拡大した汎用アイコン `iconKey`

画像がなくても、空白の画像枠やエラー表示を出さない。

### 3.3 マップ

マップ上は汎用アイコンを標準とする。

次のような見た目が重要なアイテムだけ、個別画像へ切り替えられる。

- 成長する植物
- イベント固有品
- 思い出品
- 家具、装飾品
- ユーザーが専用画像を見せたいアイテム

既定値は `icon` とし、アイテムごとに `image` へ変更可能にする。

## 4. データ形式

```ts
export type ItemVisual = {
  iconKey: string;
  genericVisualKey: string | null;
  imageAssetId: string | null;
  mapDisplayMode: "icon" | "image" | "auto";
};
```

推奨既定値：

```ts
{
  iconKey: "category",
  genericVisualKey: "misc",
  imageAssetId: null,
  mapDisplayMode: "icon"
}
```

`auto` の場合：

- 個別画像がある場合は画像
- 個別画像がない場合はアイコン

## 5. アイコンセット

Material Symbols系、または同等の単純なSVGアイコンセットを利用できる。

MVPでは次を守る。

- Google Fontsなどの外部アイコンフォントを実行時の必須依存にしない
- 使用するアイコンだけをローカルSVGまたはインラインSVGとして同梱する
- アイコン名をデータへ保存し、描画側のレジストリからSVGを取得する
- SVGが見つからない場合は `category` アイコンへフォールバックする
- アイコンだけのボタンには読み上げ名を付ける
- 色だけで意味を区別しない

## 6. 初期カテゴリと推奨アイコン

正確なアイコン名は、採用するSVGセットに合わせて実装時に確定する。

| カテゴリ | 用途 | 推奨キー例 |
|---|---|---|
| food | 食べ物、おやつ、料理 | `restaurant` |
| drink | 飲み物、マグカップ | `local_cafe` |
| plant | 種、花、植木鉢 | `potted_plant` |
| book | 本、手紙、記録 | `menu_book` |
| tool | 工具、ジョウロ、傘 | `handyman` / `umbrella` |
| craft | 材料、作りかけ | `construction` |
| photo | 写真、写真立て | `photo` |
| gift | 贈り物 | `redeem` |
| furniture | 家具、クッション | `chair` |
| clothing | 服、身につける物 | `apparel` |
| toy | ぬいぐるみ、玩具 | `toys` |
| storage | 箱、収納用品 | `inventory_2` |
| memory | 思い出品 | `favorite` |
| misc | その他 | `category` |

アイテムの名前と意味はテキストで保持するため、アイコンが完全に一致しなくてもゲーム上の意味は失われない。

## 7. カテゴリ共通画像

詳細画面用に、少数の汎用画像をプリセットとして用意できる。

すべてのカテゴリへ一枚ずつ用意する必要はない。MVPでは、次の8から10種類程度で十分。

- 食べ物、飲み物
- 植物
- 本、紙もの
- 工具、工作
- 写真、思い出
- 贈り物
- 家具、装飾
- 衣類、布もの
- 箱、収納
- その他の小物

カテゴリ共通画像は「特定のアイテムそのもの」ではなく、柔らかな抽象イラスト、棚、箱、シルエットなどにする。

例：

- 個別画像のないクッキー → food共通画像
- 個別画像のない手紙 → book共通画像
- 個別画像のない謎の部品 → tool共通画像

## 8. アイテム登録画面

### かんたん登録

必須：

1. アイテム名
2. カテゴリ

ゲームがカテゴリから、推奨アイコンとカテゴリ共通画像を自動設定する。

ユーザーはそのまま保存できる。

### こだわり設定

任意：

- アイコン変更
- 個別画像追加
- マップ表示をアイコンまたは画像へ変更
- 表示倍率、接地点
- 個人的な意味
- タグ、利用可能な操作

## 9. 個別画像の追加と削除

アイテム作成後でも、詳細画面の「画像を追加」から個別画像を登録できる。

画像を削除してもアイテム本体は削除しない。自動的にカテゴリ共通画像または汎用アイコンへ戻す。

これにより、最初はアイコンだけで作り、思い入れが強くなった品だけ後から画像を与えられる。

## 11. アクセシビリティ

- アイコンにはアイテム名またはカテゴリ名を読み上げ名として付ける
- アイコンとアイテム名を併記する
- 色だけで種類や状態を表さない
- 小さなアイコンだけをタップ対象にせず、行全体を44px以上のボタンにする
- 装飾SVGは `aria-hidden="true"`、意味を持つSVGはテキストラベルと関連付ける

## 12. オフラインと性能

- 汎用SVGはアプリへ同梱する
- 外部URLから毎回取得しない
- 一覧では大きな個別画像を読み込まない
- 詳細を開いた時だけ必要な画像Blobを読む
- サムネイルが必要になった場合は別Blobとして生成できる

## 13. 実装時期

### 先に仕様として固定する

- アイテム画像は任意
- 一覧はアイコン優先
- 詳細は個別画像、共通画像、アイコンの三段フォールバック
- マップ既定はアイコン

### Milestone 8で実装する

- アイコンレジストリ
- カテゴリからの自動選択
- アイテム一覧
- 詳細の三段フォールバック
- 個別画像アップロード
- マップ表示モード

初期のイベント実装では、絵文字や仮SVGを同じ `iconKey` の代替として使用してよい。

## 14. 完成条件

- 個別画像なしでアイテムを作成できる
- 一覧が統一されたアイコンで表示される
- 詳細画面が空白にならない
- 個別画像を後から追加、削除できる
- 画像を削除してもアイテムを使用できる
- マップ表示をアイコンまたは画像から選べる
- オフラインでも汎用アイコンが表示される
- アイコンだけに意味を依存しない
