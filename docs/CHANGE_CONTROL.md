# 仕様変更管理

最終更新日：2026-07-28

この文書は、開発途中でゴールポストが動き、最初に決めた製品から少しずつ逸れていくことを防ぐためのもの。

## 1. 仕様の種類

### 固定仕様

製品の形を決める重要な判断。

変更には、ユーザーによる明示的な承認と、この文書への記録が必要。

例：

- APIへ直接接続しない
- 家と庭を別マップにする
- 日常行動はJavaScriptで進める
- 手動相談方式
- 関係性を恋愛へ限定しない
- iPhone縦画面優先

### 実装仕様

固定仕様を実現する方法。

既存の目的を変えない範囲で改善可能。

例：

- 関数の分割
- CSSの整理
- IndexedDBストアの内部実装
- テスト方法
- アニメーション時間

### バランス値

試遊で調整する数値。

例：

- ゲーム時間倍率
- 行動点
- クールダウン
- イベント確率
- 表示時間

バランス値の調整は、製品方針変更として扱わない。ただしユーザー体験が大きく変わる場合は記録する。

## 2. 変更手順

固定仕様を変更する場合は、PRに次を記載する。

1. 現在の仕様
2. 発生している問題
3. 変更案
4. 変更しない代替案
5. MVP範囲への影響
6. 保存データへの影響
7. ユーザーの明示承認

承認後、同じPRで次を更新する。

- `docs/PRODUCT_SPEC.md`
- `docs/ROADMAP.md`（順序や範囲が変わる場合）
- この文書の決定記録

コードだけ先に変更し、仕様書を後から合わせてはいけない。

## 3. スコープ追加の扱い

新しいアイデアが出た場合、現在のMilestoneへ自動的に追加しない。

次のどれかへ分類する。

- 現在の完成条件に必要
- 次のMilestoneで扱う
- MVP後候補
- 採用しない

「便利そう」「将来必要そう」だけでは、現在のPRへ追加しない。

## 4. コンテキストが不足した場合

エージェントが会話履歴を持っていない、または仕様の意図が不明な場合：

1. `AGENTS.md` を読む
2. `docs/INDEX.md` を読む
3. `docs/PRODUCT_SPEC.md` を読む
4. `docs/ROADMAP.md` の現在地を確認する
5. 既存コードを確認する

それでも判断できない場合は、製品仕様を増やさず、最小の実装を選び、PRへ判断を記載する。

過去のチャット内容を推測して新しい仕様を作らない。

## 5. 競合を減らす運用

- 同時に複数PRを進めない
- マージ後に次の作業を開始する
- 最新mainからブランチを作る
- 一つのPRは一つの目的に限定する
- 仕様書とコードを別々の並行PRで変更しない
- 競合は作業ブランチ側で解消する
- ユーザーへモバイル画面での手動競合解消を求めない

## 6. 決定記録

### D-001：通常行動はJavaScriptで処理する

状態：確定

理由：

- 常時生成AIを呼ばない
- API料金を不要にする
- オフラインでも生活を進める
- 行動をゲームとして検証可能にする

### D-002：LLM APIへ直接接続しない

状態：確定

採用方式：

- プロンプトをゲーム内で作成
- 普段のパートナーチャットへユーザーが手動コピー
- 返答をユーザーが手動貼り付け
- JSONを検証
- 確認後に反映

注意：

この方式を「LLM接続」と呼ばない。

### D-003：パートナーの人格をゲーム側で再定義しない

状態：確定

理由：

ユーザーのパートナーチャットには、すでに人格、関係性、話し方が設定されているため。

ゲームへ保存するのはシミュレーションに必要な行動傾向だけ。

### D-004：家の中と庭を別マップにする

状態：確定

理由：

- 各マップを広く見せられる
- 天気表現を庭へ限定できる
- アイテムと人物の重なりを減らせる
- 家の外観と玄関を代理表示に使える

### D-005：別マップ人物は入口へ代理表示する

状態：確定

代理アイコンは実際の現在地を変更しない。

### D-006：カスタムマップはユーザーが地点を配置する

状態：確定

画像解析を必須にせず、地点マーカー、地点タイプ、出入口、代理位置を手動設定する。

### D-007：関係性メーターを設けない

状態：確定

恋人、家族、友人、相棒などを同じゲームシステムで扱う。

### D-008：公開プリセットはサム

状態：確定

特定ユーザーの私的パートナーを公開キャラクターとして使用しない。

### D-009：保存はIndexedDB、画像はBlob分離

状態：確定

JSONへ画像を埋め込まず、`assetId`で参照する。

### D-010：仮素材で実装し、表示規格確定後に本番素材を作る

状態：確定

理由：

描き直しとUI再設計を減らすため。

### D-011：MVPはVanilla TypeScript

状態：確定

React等の導入は、明確な必要性が生じるまで行わない。

### D-012：初期イベントは5件

状態：確定

- 知らない芽
- 急な雨
- 最後のおやつ
- 古い写真立て
- 夜の小さな音

すべて、手動相談なしで進められるプリセット結果を持つ。

## 7. 未確定で調整可能なもの

- 正式な配色
- 本番マップの絵柄
- サムの最終ビジュアル
- 主人公プリセットの種類
- ゲーム時間倍率
- 行動点の詳細
- イベント確率
- アニメーション速度
- 広告サービスと最終配置
- バックアップ内部ライブラリ

未確定項目を、エージェントが勝手に固定仕様へ昇格させない。

## 8. 変更しないことも選択肢

新しい問題が見つかった場合、必ずしも製品仕様を変える必要はない。

優先順位：

1. バグ修正
2. 表示や内部構造の改善
3. フォールバック追加
4. 実装順の調整
5. 固定仕様の変更

固定仕様の変更は最後の手段とする。
